# Musoq 17.0.6-alpha.1 - Language and Diagnostic Contracts

This full-train alpha advances the runtime-v2 language and diagnostic contracts across parsing, semantic analysis, compilation, generated execution, and end-to-end compatibility coverage.

This release publishes:

- `Musoq.Parser`
- `Musoq.Plugins`
- `Musoq.Schema`
- `Musoq.Evaluator`
- `Musoq.Converter`

## Highlights

- Added adjacent `r`/`R`-prefixed SQL raw string literals that preserve backslashes, whitespace, quotes, separators, Unicode, and other content exactly through parsing, compilation, and execution.
- Added conservative, context-aware advisory analysis for suspicious ordinary path and regex escapes, glob-shaped `LIKE` patterns, null and predicate hazards, outer-join traps, unreachable branches, unused declarations, ordering mistakes, and impossible conversions.
- Added contextual alias parsing and source-alias provenance, required stable aliases for addressable multi-source operations, and `params(...)` compatibility for canonical `param(...)` script-parameter semantics.
- Introduced structured diagnostic descriptors, registries, phases, source domains, related locations, safe arguments, suggested actions, stable formatting metadata, and migration metadata.
- Propagated source origins and spans through Execution IR, generated C#, Roslyn/interpreter trees, and target reporting while preserving target-native details and safe runtime failure envelopes.
- Preserved the existing public Schema exception constructor and factory signatures while adding reason-aware overloads for binary compatibility.
- Added broad parser, evaluator, converter, schema, execution-target, generated-artifact, cache, asynchronous, lifecycle, and compatibility coverage for the new contracts.

## Compatibility

- Ordinary SQL strings retain escape interpretation. Use `r'...'` or `R'...'` when a path, regular expression, or other value must preserve backslashes and content literally.
- Multi-source `JOIN`, `APPLY`, derived, `VALUES`, `PIVOT`, and `UNPIVOT` operations require stable addressable aliases where the source must be referenced; malformed or ambiguous forms now receive precise diagnostics.
- `params(...)` is accepted contextually as a compatibility spelling for the canonical `param(...)` script-parameter block and does not change plural parameter semantics.
- Diagnostic taxonomy and formatting are now descriptor-backed. Retired ambiguous diagnostic values are not reused; callers should follow the active catalog and migration metadata.
- Existing `MethodResolutionException` and `SchemaArgumentException` public constructors and factories remain available; the new diagnostic-reason overloads are additive.
- No standalone target package is introduced. Target implementations remain bundled through `Musoq.Converter`.
