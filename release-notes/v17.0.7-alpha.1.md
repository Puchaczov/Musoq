# Musoq 17.0.7-alpha.1 - Query-scoped CLR rows for dynamic sources

This full-train alpha adds an optional, format-neutral query-scoped CLR row transfer path for dynamic data sources. When planning has exact projected metadata, a compatible source and target, and no declared-entity dependency, the compiler can materialize rows into a private carrier owned by the collectible compiled-query assembly.

This release publishes:

- `Musoq.Parser`
- `Musoq.Plugins`
- `Musoq.Schema`
- `Musoq.Evaluator`
- `Musoq.Converter`

## Highlights

- Added the additive `Musoq.Schema` contracts for `QueryRowShape`, `QueryRowField`, source transfer capabilities, query-scoped source requests, concrete field readers, and generic row materializers.
- Added exact field-shape validation for dense slots, deterministic fingerprints, source ordinals and names, nullability, arrays, closed generics, visibility, and unsupported CLR types.
- Added planner-owned transfer decisions that preserve source identity, projected fields, carrier lifetime, carrier kind, capability requirements, cache identity, and deterministic fallback reasons through physical planning and Execution IR.
- Added generated private readonly struct carriers for conservative scan-local payloads up to 64 bytes and sealed class carriers for wider or escaping lifetimes. Shape metadata is hoisted into the collectible generated query type for warm execution.
- Added generated materializers that call concrete/ref-struct readers through `Read<T>(slot)` without object-array row storage, reflection, delegates, boxed readers, or per-field interface dispatch in the hot loop.
- Added lifecycle, cancellation, disposal, pushdown, early-termination, conversion, materializer-failure, join, outer-join, grouping, window, CTE, set-operation, chunk-boundary, cache-isolation, runtime-mismatch, unload, and constrained-IL coverage.
- Added a concrete CSV query-row source with header/ordinal metadata, source-local predicate/order/slice planning, ref-struct reading, diagnostics, cancellation, chunking, and the explicit `enableQueryScopedRows: false` legacy comparison path.
- Added canonical generated-code samples Q236-Q241, benchmark baselines and qualification gates, provider implementation guidance, and the format-neutral [query-scoped dynamic source documentation](../docs/query-scoped-dynamic-sources.md).

## Compatibility

- Query-scoped transfer is optional. Existing providers and consumers continue to use `GetRowSource<T>` when they do not advertise the capability or when exact metadata, target support, source identity, or query shape makes the optimized path ineligible.
- Declared-entity-dependent calls using `InjectSource` or `InjectSpecificSource` remain on the provider's declared entity path; the planner does not replace that contract with a generated carrier.
- Runtime capability changes after compilation fail deterministically with the source identity and shape fingerprint rather than silently retrying through the legacy path.
- Existing `source-access-v1` and Host ABI v2 behavior is preserved. Query-scoped transfer uses the separate `query-row-source-access-v1` host import.
- No standalone target package is introduced; target implementations remain bundled through `Musoq.Converter`. No external `Musoq.DataSources` package changes are included in this release.
