# Musoq 17.0.4-alpha.1 - Evaluator Compilation and Target Contract Improvements

This full-train alpha improves runtime-v2 compilation throughput and generated execution while hardening target compatibility contracts.

This release publishes:

- `Musoq.Parser`
- `Musoq.Plugins`
- `Musoq.Schema`
- `Musoq.Evaluator`
- `Musoq.Converter`

## Highlights

- Added parsed-query, semantic-template, and canonical execution artifact caches keyed by immutable semantic contracts, separating reusable executable artifacts from runtime and provider bindings.
- Added batched evaluator compilation, shared C# compilation and assembly loading, direct syntax-tree compilation, structural generated-code hashing, and purpose-aware inspection versus execution rendering.
- Reduced generated execution overhead through typed correlation and join keys, reusable window row carriers, direct table projection paths, reflection-free field access, row-shape/value-tuple support, and optimized codegen cleanup.
- Added profiled and unprofiled execution paths, phase telemetry, benchmark samples, corpus inventory/measurement scripts, compilation batching, and bounded wall-time and duration guardrails.
- Added case-insensitive C# postfix cast aliases across scalar, method-call, aggregate, and window expressions with strict null and failure semantics; documented the syntax and expanded parser/evaluator coverage.
- Bumped the host ABI contract to version 2, added canonical portable symbol-definition comparison and ABI-definition hashes, deduplicated equivalent imports, and rejected conflicting host requirements.
- Preserved single evaluation for nullable boolean rewrites and expanded recovery, artifact lifecycle, target compatibility, repeated-compilation, cache safety, generated-code shape, and performance coverage.

## Compatibility

The host execution ABI is intentionally versioned as v2. Generated execution artifacts and target contracts created for the previous ABI must be regenerated for this release. No new standalone target packages are introduced; target implementations remain bundled through `Musoq.Converter`.
