# Musoq 17.0.0-alpha.4 - Runtime V2 Parameter Contracts

This alpha release makes runtime-v2 script parameter ownership stricter and gives hosts a canonical parameter contract API, so hosts no longer need to mirror SQL parsing to validate runtime inputs or build cache keys.

This is a full-train prerelease for:

- `Musoq.Parser`
- `Musoq.Plugins`
- `Musoq.Schema`
- `Musoq.Evaluator`
- `Musoq.Converter`

## Highlights

- Added `MQ7006_UnknownScriptParameter` and strict unknown runtime parameter rejection.
- Runtime parameter binding now rejects extra supplied parameters even for scripts that declare no parameters.
- Preserved existing precedence: missing required parameters, nullability violations, and exact CLR type mismatches are reported before unknown-extra diagnostics.
- Added canonical `ScriptParameterContract` metadata with declared type names, canonical engine type names, CLR type, nullability, collection element type, and default metadata.
- Added a shared script parameter type catalog for aliases such as `bit`, `boolean`, `money`, `guid`, `datetimeoffset`, `timespan`, nullable declarations, and arrays.
- Exposed parameter contracts through compiled query, typed/profile query, generated runnable, and typed artifact APIs while retaining `ParameterDefinitions`.
- Added runtime-v2 contract signature constants and included the signature in artifact metadata, semantic shape hashes, typed artifacts, and execution compilation cache keys.
- Added `UseCteSidecarIndexes` to the execution compilation cache key.
- Fixed CTE sidecar join-chain lowering for final filters that reference aliases introduced by sidecar probes.

## Compatibility

Unknown runtime parameters are now rejected instead of ignored. Hosts should remove stale or misspelled runtime parameter entries before calling `Run`.

Hosts should use `ParameterContracts` as the canonical runtime-v2 parameter metadata surface. `ParameterDefinitions` remains available for compatibility.
