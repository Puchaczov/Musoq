# Musoq 17.0.0-alpha.1 - Runtime V2 Preview

This is the first alpha release for the Runtime V2 language and query surface. The notes below are derived from the `specs/` changes between `master` and the runtime-v2 branch and focus on user-visible syntax, query behavior, and source integration contracts.

This is a full-train prerelease for:

- `Musoq.Parser`
- `Musoq.Plugins`
- `Musoq.Schema`
- `Musoq.Evaluator`
- `Musoq.Converter`

## Highlights

- Expanded the core SQL language with script `param(...)` blocks, compile-time `let` variables, derived tables, inline `VALUES` row sources, richer subqueries, full outer joins, semi joins, anti joins, aggregate `FILTER`, `PIVOT`, `UNPIVOT`, window frames, and `QUALIFY`.
- Added Runtime V2 casting and grouping rules: strict postfix casts use `expr::TypeName`, `GROUP BY` supports positional references, and `GROUP BY ALL` can infer grouping keys from non-aggregate projections.
- Expanded projection shaping with SELECT alias visibility rules, CTE output-name rules, and star modifiers including `LIKE`, `EXCLUDE`, `REPLACE`, and `RENAME`.
- Added richer predicate support including `!=`, `IN $collectionParameter`, `EXISTS`, scalar subqueries, quantified `ANY` / `SOME` / `ALL`, `CONTAINS`, and multi-field `any(...)` / `all(...)` pattern predicates.
- Added null-aware query features including `IS DISTINCT FROM`, `IS NOT DISTINCT FROM`, alias-level `IS PRESENT` / `IS MISSING`, and the null fallback operator.
- Expanded APPLY support with scalar complex objects, derived-table APPLY sources, and `WITH ORDINALITY`.
- Improved ordering and ASOF joins with `NULLS FIRST` / `NULLS LAST` and deterministic duplicate-candidate handling through `TIE BREAK BY`.
- Added `DESC SETTINGS` and `DESC QUERY` for inspecting source runtime setting requirements and projected query output metadata.
- Added a Runtime V2 compiled artifact API for host-managed cross-process query artifact persistence, with diagnostic-aware compile/load methods and optional custom type loading.
- Extended TABLE/COUPLE with source runtime settings profiles and column read modifiers such as `encoding`, `culture`, `format`, `trim`, and `source <key> '<value>'`.
- Extended binary interpretation schemas with field value validation (`const`, `magic`, `oneOf`), `repeat until eof`, tagged-union `switch` payloads, and length-bounded `substream` payloads.

## Breaking And Migration Notes

- Interpretation functions now use generic schema syntax:
  - `Interpret<Header>(bytes)` instead of `Interpret(bytes, Header)`
  - `Parse<LogEntry>(text)` instead of `Parse(text, LogEntry)`
  - `TryInterpret<T>(...)`, `TryParse<T>(...)`, `InterpretAt<T>(...)`, `PartialInterpret<T>(...)`, and `PartialParse<T>(...)` follow the same pattern.
- Interpretation functions remain APPLY-only. Use `CROSS APPLY` or `OUTER APPLY`; inline property access such as `Interpret<Header>(bytes).Magic` is still reserved for a future version.
- The old bare `::N` grouping shorthand is removed. `::` is now postfix cast syntax only. Use `GROUP BY` ordinals or aliases instead.
- Strict postfix cast targets are CLR-style type names such as `Int32`, `Decimal`, or `DateTime`. SQL type aliases such as `INTEGER`, `VARCHAR`, and `DOUBLE PRECISION` are not cast targets.
- Invalid strict casts throw instead of using the softer behavior of helper functions such as `ToInt32(...)`.
- Script parameters must be declared in an optional leading `param(...)` block. Supplied parameter values are checked against the declared CLR type; Musoq does not parse strings or perform numeric conversion for supplied values.
- Parameters used as schema source arguments must be direct `$name` arguments and must declare defaults. Use `let` values for compile-time source-argument expressions.
- Plain derived tables in `FROM` or `JOIN` are not lateral. Use `CROSS APPLY` or `OUTER APPLY` when the derived query needs to reference an outer source alias.
- CTE and derived-table consumers see only exported output column names. Source aliases used inside a CTE or derived table are not exported.
- `ORDER BY` after a set operation currently applies to the rightmost query, not to the combined set result. Wrap the set operation in a CTE and order the outer query when whole-result ordering is required.
- Binary/text schema helper `ToString(byte[], encoding)` is now `ToText(byte[], encoding)`.
- Binary schema validation is stricter. Invalid bit widths, alignment values, and negative constant sizes are compile-time diagnostics instead of late runtime failures.
- Some interpretation diagnostics were normalized to four-digit codes such as `ISE0001`, `ISE0002`, `ISE0003`, and `ISE0007`.

## Core SQL Runtime V2

### Script Values

- Added an optional leading `param(...)` block for typed host-supplied values.
- Added scalar and one-dimensional collection parameter types. Collection parameters are intended for `expr IN $name` and `expr NOT IN $name`.
- Added immutable `let name: type = constantExpression` declarations for compile-time script values.
- `param(...)` and `let` share the `$name` reference namespace and reject duplicate names.
- Added diagnostics for malformed declarations, duplicate parameter blocks, duplicate names, undeclared `$name` references, unsupported types, invalid defaults, invalid source-argument usage, and runtime parameter mismatches.

### Projection And Row Shaping

- SELECT aliases now have defined same-query visibility:
  - non-aggregate aliases can be used in `WHERE` and `GROUP BY` when no source column with the same name exists
  - aggregate aliases can be used in `HAVING`
  - aggregate aliases are rejected in `GROUP BY`
- CTEs and derived tables expose projection output names only. Explicit SELECT aliases define exported names, and source qualifiers from the inner query do not escape.
- Star expressions now have defined modifier order: `LIKE` / `NOT LIKE`, then `EXCLUDE`, then `REPLACE`, then `RENAME`.
- Star modifier validation now rejects missing targets, duplicate modifier entries, removing every column, replacing excluded columns, and rename collisions.
- Qualified stars inside CTEs and derived tables export source column names, not source-qualified names.

### Sources, Subqueries, And Set Operations

- Added derived tables as `FROM` and `JOIN` sources. Derived tables must have aliases and are independent unless used through APPLY.
- Added inline `VALUES` row sources with strongly typed fields, typed numeric literal suffixes, base-prefixed numeric literals, `NULL` type inference, and scalar `param` / `let` support.
- Added predicate subqueries for `IN`, `NOT IN`, `EXISTS`, and `NOT EXISTS`.
- Added scalar subqueries in expression contexts.
- Added quantified subqueries with `ANY`, `SOME`, and `ALL`.
- Added collection-parameter membership predicates through `IN $name` and `NOT IN $name`.
- Set operations now document omitted keys, empty key lists `()`, and explicit key lists such as `UNION (key_col)`. Both sides must still project compatible shapes.

### Predicates And Null Handling

- Added `!=` as an alternative not-equal operator.
- Added `IS DISTINCT FROM` and `IS NOT DISTINCT FROM` for null-safe equality checks.
- Added alias-level `IS PRESENT` and `IS MISSING` for aliases that can be absent because of outer joins, outer apply, or ASOF left joins.
- Added `??` as a right-associative null fallback operator.
- Added `CONTAINS` with explicit null behavior.
- Added multi-field pattern predicates such as `any(Name, Message) LIKE '%error%'` and `all(a, b) NOT RLIKE pattern`.

### Joins And APPLY

- Added FULL OUTER JOIN.
- Added SEMI JOIN and ANTI JOIN for existence and non-existence joins.
- Added CROSS JOIN as an explicit Cartesian-product join.
- Expanded multi-source method resolution rules and ambiguity diagnostics.
- Added `TIE BREAK BY` for ASOF duplicate-candidate selection.
- Added `NULLS FIRST` and `NULLS LAST` support to top-level ordering, window ordering, and ASOF tie-break ordering.
- Added APPLY `WITH ORDINALITY`, exposing a zero-based `Ordinal` column on the right-side APPLY alias.
- Added APPLY with derived tables for correlated row expansion.

### Aggregation, Pivoting, And Windows

- Added GROUP BY positional references.
- Added `GROUP BY ALL`, which infers every non-aggregate, non-window SELECT expression after projection expansion.
- Added aggregate `FILTER (WHERE ...)`, including use with `DISTINCT` and aggregate window functions.
- Added static `PIVOT` with mandatory static `IN (...)` values and aggregate measures.
- Added explicit-row `UNPIVOT` with static `IN (...)` values, `KEEP` fields, and null-preserving rows.
- Expanded window support with named `WINDOW` clauses, frame syntax, `ROWS BETWEEN`, partial `RANGE BETWEEN`, ranking, offset, aggregate, and value-access functions.
- Added custom window function registration.
- Added `QUALIFY` to filter after window function computation and before `ORDER BY`, `SKIP`, and `TAKE`.

### Metadata And Diagnostics

- Added `DESC SETTINGS` for schema methods and coupled aliases. It reports setting names, types, required/default status, and resolution status without exposing setting values.
- Added `DESC QUERY (<query>)` to compile a query and return projected output metadata without executing data rows.
- Added diagnostics for invalid subquery shape/scope, invalid `VALUES`, invalid `PIVOT` / `UNPIVOT`, invalid `QUALIFY`, invalid aggregate `FILTER`, invalid window frame usage, strict cast targets, star modifiers, script parameters, and script variables.

## Interpretation Schemas

- Binary and text interpretation calls now consistently use generic schema syntax.
- Binary schemas now support inline value constraints:
  - `const` and `magic` for exact expected values
  - `oneOf` for explicit allowed value sets
- `repeat until eof` reads zero or more elements until the current input span is exhausted, including inside bounded substreams.
- `switch` fields model tagged-union payloads with a selected `Case` member and one nullable member per branch.
- `substream[length] raw` and `substream[length] as Type` let nested parsers operate inside a length-bounded slice, with `exact` and `lax` modes.
- Compile-time validation now catches invalid field constraints, unsupported switch branches, invalid substream declarations, invalid bit widths, and invalid constant sizes earlier.

## TABLE, COUPLE, And Source Contracts

- The TABLE/COUPLE specification is now versioned as `1.1.0`.
- TABLE columns can now carry datasource read hints:
  - `encoding 'windows-1250'`
  - `culture 'pl-PL'`
  - `format '#,##0.00'`
  - `trim`
  - `source codec 'base64'`
- Read modifiers are stored as per-column key/value metadata. The core engine preserves them through metadata, planning, and execution contexts, but datasource implementations decide what each modifier means.
- Modifier keys are lowercase; `source` modifiers are stored as `source.<identifier>`. `trim` stores the string value `true`.
- There are no table-level read-modifier defaults. Missing modifiers mean datasource defaults.
- Duplicate read-modifier keys on one column are invalid, including duplicate `source.<identifier>` keys.
- COUPLE can bind a schema method to a table, a source runtime settings profile, or both:
  - `couple api.items with settings prod as Items`
  - `couple api.items with table Item and settings prod as Items`
- `table` and `settings` options can appear in either order, but duplicate options and empty `with` clauses are invalid.
- Settings-only couples infer table metadata from the underlying schema. Table-and-settings couples use the declared table shape and selected settings profile.
- The same schema method can be coupled more than once with different aliases and different settings profiles.
- Source runtime setting values stay outside SQL and are resolved by the host.
- Datasources can report source contract diagnostics from `DescribeSource` or `TryPlanSource` for unsupported modifiers, malformed modifier values, and table/source mismatches.
- Source contract diagnostics map severity to behavior: info appears in planning text, warning uses `MQ5013`, and blocking error uses `MQ3071`.
- Diagnostics should point at the read modifier when possible, then the column declaration, then the normal empty-span fallback.
- TABLE definitions still appear before COUPLE statements that reference them. COUPLE statements can follow only the TABLE definitions they need.

## AI Interpretation Spec Alignment

- AI examples were aligned with generic binary/text interpretation syntax.
- `Infer(content)` is documented as the AI equivalent of `Interpret<Schema>(...)` and `Parse<Schema>(...)`.

## Known Preview Scope

- This is an alpha release. Runtime V2 syntax and diagnostics are expected to stabilize through preview and RC releases.
- Inline property access on interpretation functions remains reserved.
- Extended binary switch forms such as range cases, expression cases, and direct arrays of switch fields remain reserved for future versions.
