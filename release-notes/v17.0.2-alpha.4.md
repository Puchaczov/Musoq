# Musoq 17.0.2-alpha.4 - Complex Query Coverage and Nullable Execution

This full-train alpha strengthens complex-query execution coverage and result-contract verification across the Musoq runtime-v2 pipeline.

This prerelease is for:

- `Musoq.Parser`
- `Musoq.Plugins`
- `Musoq.Schema`
- `Musoq.Evaluator`
- `Musoq.Converter`

## Highlights

- Added PostgreSQL-shaped basic recursive CTEs with CTE column lists, `UNION ALL`, full-row `UNION`, and Musoq keyed `UNION (columns)` identity.
- Added iterative typed fixed-point code generation, shallow-value invariant snapshots, direct reusable indexes, cancellation, independent row/iteration/snapshot limits, and recursive plan/profile inspection.
- Added 229 current generated-code samples and 13 profiled samples, including hardened recursive/CTE shapes, 68 supported result contracts, 51 unsupported diagnostic contracts, computed pair coverage, and scoped mutation checks.
- Added eight-scenario handwritten semi-naive gates plus full-mode, overhead, compilation, and ordinary-CTE before/after regression tiers.
- Added comprehensive exact-schema and exact-row contracts for complex joins, APPLY, CTE, set, grouping, ordering, DISTINCT, window, `QUALIFY`, ASOF, pivot/unpivot, TABLE/COUPLE, text, and binary query fixtures.
- Added a syntax-coverage inventory and stricter evaluator guardrails that reject partial materialized-result assertions while preserving diagnostics, planning, generated-code, and direct interpreter tests.
- Expanded runtime coverage for TABLE/COUPLE type syntax, nullable values, aliases, predicates, boolean conversion, pattern matching, `GROUP BY ALL`, `DESC QUERY`, text formats, and binary formats.
- Improved nullable scalar type inference and source materialization in `Musoq.Evaluator`.
- Added null-aware `NOT IN` subquery rewriting so null-containing and correlated subqueries preserve SQL null semantics.
- Improved nullable enumerable element handling in `Musoq.Targets.CSharpClr`.
- The CSharpClr target changes are shipped inside the `Musoq.Converter` package; CSharpClr remains a non-packable implementation assembly.
- `Musoq.Schema` and `Musoq.Plugins` remain protected by same-major datasource ABI validation during packaging.

## Compatibility

Existing supported query shapes remain compatible. `RECURSIVE` remains contextual, so an ordinary CTE may still be named `recursive`. Recursive CTEs add an optional `RecursiveCteExecutionLimits` configuration surface; the existing `CompilationOptions` constructor and the two-argument limit constructor remain source-compatible. Exported CTE columns are case-insensitive, keyed recursive identity binds only to exported names, and local-server limits are hard ceilings. The feature provides basic PostgreSQL-style syntax rather than complete PostgreSQL recursive-query compatibility, and keyed `UNION` is a Musoq extension.

Release verification passed with 16,611 core tests and 6,257 Cloud tests, with four intentional core refresh utilities and 23 integration/playground tests skipped. Changed-line coverage reached 94.21% in core and 96.43% in Cloud. The six-tier recursive performance gate remained inside its 1.25x time, 1.20x allocation, and 1.03x regression ceilings.
