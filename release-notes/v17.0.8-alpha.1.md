# Musoq 17.0.8-alpha.1 - Query semantics, guarded execution, and runtime telemetry

This full-train alpha consolidates the Runtime V2 planning, execution, parser,
generated-code, and telemetry work accumulated since `17.0.7-alpha.1`.

This release publishes:

- `Musoq.Parser`
- `Musoq.Plugins`
- `Musoq.Schema`
- `Musoq.Evaluator`
- `Musoq.Converter`

## Highlights

### Parser and language contracts

- Hardened wildcard and `SELECT *` modifier metadata discovery so dynamic
  metadata is isolated by query scope and does not leak between related
  queries or cached interpretation schemas.
- Strengthened star-modifier semantics and diagnostics, including the
  executable migration guidance for set-result modifier placement.
- Carried source-parameter, range-frame, set-operation, and Runtime V2 syntax
  contracts through parser diagnostics, language specifications, and feature
  coverage evidence.

### Datasource parameters and metadata

- Added required runtime datasource-parameter binding with deterministic
  defaults and preserved positional compatibility.
- Traversed nested source-parameter arguments consistently through metadata,
  planning, and execution paths.
- Kept datasource contracts additive and compatible: no changes are required
  from existing `ISchema`, `ISchemaProvider`, `RowSource<T>`, or query-scoped
  source implementations for query progress.

### Query planning and execution semantics

- Isolated cached interpretation schemas by query scope and strengthened
  dynamic wildcard metadata behavior.
- Made sibling pipeline fusion registry-backed and deterministic.
- Applied `ORDER BY`, `OFFSET`, and `LIMIT` semantics to complete set-result
  trees rather than individual set branches.
- Standardized `RANGE` window-frame behavior and added distribution ranking
  execution for `PERCENT_RANK` and `CUME_DIST`.
- Added planner-owned guard plans for `CROSS APPLY` and `OUTER APPLY`, carried
  them through physical planning and Execution IR, and preserved early
  predicate pruning, residual predicates, and outer-row null extension in
  generated execution.

### Runtime query progress

- Added the opt-in `QueryProgress` API with `QueryProgressEventHandler`,
  monotonic `QueryProgressEventArgs`, configurable row/time cadence, and the
  optional `IQueryProgressSource` contract.
- Counts rows consumed from physical source chunks, reporting query-wide and
  source-specific counters without requiring datasource API changes.
- Publishes at the configured row or time threshold and flushes pending counts
  on successful completion, cancellation, failure, or deferred enumerator
  disposal.
- Keeps one root progress stream per run; CTE and set-operation child IDs
  remain available through phase telemetry.
- Preserves the original chunk enumerable and avoids progress configuration
  allocations when no handler is installed. Active reporting uses atomic
  counters and publication-only synchronization, with callbacks outside the
  generated per-row loop.

### Truthful phase telemetry and generated C#

- Replaced renderer heuristics based on generic execution nodes with explicit
  `ExecutionPhaseBoundary` IR nodes.
- `Begin`, `From`, `Where`, `GroupBy`, `Select`, and `End` are now once-per-scope
  entry markers at the corresponding execution boundaries. Aggregate-only
  queries do not imply `GroupBy`, and internal guards, `HAVING`, `QUALIFY`, and
  `CASE` branches do not imply `Where`.
- Preserved stable root, CTE, set-operation, and parallel child query IDs and
  kept phase calls outside generated row loops.
- Propagated progress and phase context through table, typed, asynchronous,
  profiled, contextual, and decorated execution paths, including deferred
  materialization and fallback paths.

## Compatibility

- Query progress is opt-in. Existing consumers that do not subscribe retain
  the original source enumeration behavior and existing datasource contracts.
- `DataSourceProgress` remains datasource-owned lifecycle/totals telemetry;
  `QueryProgress` is engine-owned approximate source-row consumption;
  `PhaseChanged` is engine-owned clause-entry telemetry.
- Public phase names and query-ID formats remain compatible. Their timing is
  corrected to reflect actual clause entry.
- No standalone target package is introduced; target implementations remain
  bundled through `Musoq.Converter`.
- No `Musoq.DataSources` or `Musoq.Cloud` repository changes are included in
  this release. Cloud/CLI exposure of the new engine progress stream remains a
  consumer follow-up.

## Manual impact

This is a core parser, evaluator, converter, schema-contract, and execution
release. It does not change CLI commands, service behavior, supported tool
endpoints, installer behavior, or the Cloud-owned CLI manual. The development
manual applicability audit was run for this release and is recorded as part
of the release verification.
