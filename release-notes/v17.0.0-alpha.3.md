# Musoq 17.0.0-alpha.3 - Runtime V2 Artifact Loading Fixes

This alpha release tightens runtime-v2 compiled artifact loading after API review feedback. It keeps host cache policy outside the engine while making cache hits faster, artifact compatibility stricter, and default byte loading lifecycle-aware.

This is a full-train prerelease for:

- `Musoq.Parser`
- `Musoq.Plugins`
- `Musoq.Schema`
- `Musoq.Evaluator`
- `Musoq.Converter`

## Highlights

- Updated compiled query artifacts to format version `2`.
- Added fast default artifact validation that stops after parse, semantic analysis, source runtime setting resolution, and source planning.
- Added `SemanticShapeSha256` metadata so fast loads can validate script/schema shape without regenerating executable C#.
- Added `CompiledQueryArtifactLoadOptions` and `CompiledQueryArtifactValidationMode.StrictGeneratedCodeHash` for opt-in generated-code hash validation.
- Added `CompiledQueryArtifactLoadResult` and `CompiledQueryArtifactLoader` so custom loaders can return a runnable type plus a lifetime owner.
- Changed the default artifact byte loader to use a collectible assembly load context.
- `CompiledQuery` now implements `IDisposable`; disposing it releases the runnable and artifact loader lifetime.
- Strengthened artifact engine signatures with assembly informational versions and module IDs.

## Compatibility

Artifacts produced by `17.0.0-alpha.2` use format version `1` and are rejected cleanly by this release. Hosts should rebuild stored runtime-v2 artifacts after upgrading.

Hosts still own cache keys, persistence, invalidation, eviction, encryption/compression, cleanup, plugin/catalog signatures, and tenant or process isolation.
