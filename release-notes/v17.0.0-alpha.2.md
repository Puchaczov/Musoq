# Musoq 17.0.0-alpha.2 - Runtime V2 Compiled Artifacts

This alpha release adds a runtime-v2 compiled artifact API for hosts that need to persist compiled query artifacts across process restarts without relying on engine-private compilation caches or old runtime-v1 build-chain APIs.

This is a full-train prerelease for:

- `Musoq.Parser`
- `Musoq.Plugins`
- `Musoq.Schema`
- `Musoq.Evaluator`
- `Musoq.Converter`

## Highlights

- Added public runtime-v2 compiled artifact primitives in `Musoq.Converter`:
  - `ICompiledQueryArtifact`
  - `CompiledQueryArtifact`
  - `ArtifactBuildResult`
  - `CompiledQueryArtifactTypeLoader`
- Added `InstanceCreator.CompileArtifactWithDiagnostics(...)` to produce portable assembly/symbol bytes and artifact metadata while preserving diagnostic-aware compilation behavior.
- Added `InstanceCreator.CreateExecutableFromArtifactWithDiagnostics(...)` to validate an artifact against the current script, schema provider, compilation options, engine version, and generated code shape before creating a fresh `CompiledQuery`.
- Added default artifact loading from bytes with `Assembly.Load(byte[], byte[]?)`.
- Added a per-call custom runnable type loader so hosts can use their own `AssemblyLoadContext` strategy.
- Artifact loading rebinds the current `ISchemaProvider`, source runtime settings, source runtime setting descriptions, source execution plans, and logger.
- Added `MQ8002_CompiledArtifactIncompatible` for clean diagnostics when an artifact cannot be used.

## Host Responsibilities

The engine only provides artifact primitives, validation, and loading hooks. Hosts remain responsible for cache keys, storage, invalidation, eviction, force refresh, plugin/catalog/version signatures, cleanup, encryption/compression, and tenant or process isolation.
