# Musoq 17.0.12-alpha.1 - native typed execution and SQL contracts

This full-train alpha publishes `Musoq.Parser`, `Musoq.Plugins`, `Musoq.Schema`, `Musoq.Evaluator`, and `Musoq.Converter` at `17.0.12-alpha.1`. Changes are described relative to the published `v17.0.11-alpha.1` release; the intervening `17.0.11-alpha.2` package notes describe local preparation, not a public NuGet release.

## Native typed execution

- Preserve concrete source rows, field presence, structured parameters, nested records/collections, keys, state, and final results throughout the execution pipeline.
- Support typed result getters and DTO/tuple consumption, with explicit result ownership and eligible direct result-row construction.
- Let libraries own immutable SQL declarations and concrete aggregate/window kernels, including overload selection, inherited declarations, exact signature validation, and independent state.
- Keep planning and scheduling in the engine. Custom sources/functions remain serial unless explicit execution permissions permit concurrency.
- Carry planner-selected typed columnar materialization through Execution IR and generated code; rendering emits the selected strategy.

## SQL behavior and diagnostics

- Correct correlated APPLY, quantified subqueries, nullable range/ASOF probes, CTE definition binding, duplicate export positions, and structural dependency-cycle rejection.
- Preserve nullable set operands, distinct complete-row INTERSECT results, and scalar-subquery cardinality after filtering/paging; MQ7016 reports multiple remaining rows.
- Preserve window ordering inputs, frames, named windows, structural results, input defaults, collection snapshots, and source lifecycle ownership.
- Validate TABLE declarations against authoritative provider types, nullability, enum identity, and source storage metadata.
- Preserve complete source-local negated predicates; unsafe transfers remain runtime evaluation. Carry three-valued membership, numeric promotion, single evaluation, and dynamic-member short-circuiting consistently through planning and execution.
- Limit LIKE/RLIKE matching through `CompilationOptions.WithRegexMatchTimeout`, defaulting to two seconds. Timeout failures report MQ7017 without disclosing private inputs or pattern text.
- Improve binary/text interpretation, computed field inference, nested schemas, named captures, repeated inline elements, escaped delimiters, and safe structured diagnostics.

## Breaking changes and migration

- Implicit simple-column and wildcard projections expose unqualified output names. Use an explicit alias matching the required label when a consumer requires the previous qualified name; assign unique aliases when name-based consumption would otherwise be ambiguous. Positional outputs preserve duplicate positions.
- Sources and libraries must implement native typed execution contracts. Legacy object-valued execution access, erased adapters, and aggregate/window factories are removed. Rebuild providers against the complete `17.0.12-alpha.1` train and migrate kernels and row contracts using the current source/schema contracts and [typed library example](https://github.com/Puchaczov/Musoq/blob/v17.0.12-alpha.1/docs/examples/typed-library/InvoiceLibrary.cs).
- Integral `Avg` returns `decimal?`; other numeric average types are retained. `Sum`, `Min`, and `Max` preserve nullable numeric input types; `Count` returns `long`. Null numeric inputs are ignored, empty non-count aggregates return null, and empty counts return zero. String extrema use ordinal comparison.
- Execution artifact contracts are versioned. Regenerate artifacts compiled against incompatible older contracts.
- `Musoq.Schema` and `Musoq.Plugins` intentionally do not promise binary/source compatibility with previous 17.x packages. The release packer skips their datasource ABI baseline check under the explicit alpha policy; this is not stable compatibility qualification.
- `Musoq.Targets.CSharpClr` and the other required target assemblies remain bundled through `Musoq.Converter`, with no new standalone target packages.
- Target .NET 10 using the pinned SDK `10.0.401` or a compatible newer 10.0 feature band. Cloud/DataSources upgrades and releases are separate from this Core publication.

## Documentation audit

The current Cloud manual uses `scripts/sync-specs.ps1` and `scripts/manual/Sync-Manual.ps1`; the older `Test-ManualFreshness.ps1` entrypoint is absent. Its native plugin authoring guide already describes the new typed execution contracts, but the three imported Core specifications require a refresh against this train. The downstream refresh also needs updated source-backed discovery evidence for binary-field scoping and portable TABLE type names. Cloud documentation, dependency upgrades, and their qualification are explicitly deferred to Cloud's separate waves. No Cloud changes, CLI executable, or CLI manual release archive are included in this Core publication. Core's canonical specifications and examples are included in the source release.
