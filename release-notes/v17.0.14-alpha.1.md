# Musoq 17.0.14-alpha.1 - language and interpretation specifications 2.0.0

This full-train alpha releases Musoq.Parser, Musoq.Plugins, Musoq.Schema,
Musoq.Evaluator, and Musoq.Converter at `17.0.14-alpha.1`. Changes are described
relative to `v17.0.13-alpha.1`. Upgrade all five packages together. Execution
targets remain bundled through Converter; no standalone target package is added.

## SQL semantics and query execution

- Implement lazy three-valued Boolean evaluation, implicit-null CASE results,
  null-propagating string concatenation, lossless numeric conversion, deterministic
  overload resolution, nullable set outputs, and structured overflow diagnostics.
- Correct aggregate-star syntax, FILTER exclusion, frame-sensitive window value
  functions, keyed set equality and multiplicity, and UNION survivor ordering.
- Add general correlated execution for scalar, EXISTS, IN, ANY/SOME/ALL, and
  negated subqueries while preserving scope, clause timing, cardinality,
  cancellation, disposal, and applicable specialized strategies.
- Support computed datasource arguments and direct PARAM, PARAMS, and LET paging
  counts, validating typed SKIP and TAKE values before opening sources.
- Negotiate constant RLIKE and NOT RLIKE source pushdown with safe residual
  filtering and regex timeout diagnostics.

## Binary and text interpretation

- Align schema expressions with core null, conversion, CASE, and Boolean rules.
  Validate nested declarations, patterns, captures, references, and modifiers;
  recover only from typed interpretation failures.
- Make repetition limits configurable and correct EOF, delimiter, progress,
  rollback, nested failure, and exact/lax substream behavior.
- Support recursive binary compositions and general text-switch result bodies.
  Preserve capture, record, array, and union shapes through projection,
  interpretation, APPLY, CTEs, recursive queries, and null-extended rows.
- Expose precise partial-result bit offsets and completion state; serialize only
  completed payload members.

## Coupling, compiler, and coverage

- Reconcile TABLE and COUPLE grammar, names, declaration order, description
  calls, duplicate diagnostics, and validation before source opening.
- Freeze resolved settings and status snapshots. Document host-owned profiles,
  secret-free settings descriptions, and per-source isolation.
- Isolate branch predicate and intermediate producer identities. Streamline
  canonical compilation identity, execution traversal, pruning, expression
  analysis, invariant motion, row-shape ownership, and namespace resolution.
- Extend parser, binding, execution, interpreter, diagnostic, provider-contract,
  serialization, target, generated-code, and artifact regressions, including
  QUALIFY activation with changing providers and overlapping executions.
- Advance core, interpretation, and coupling specifications to 2.0.0; refresh
  generated samples and provider-independent specification and README examples.
- Replace the previous benchmark suites, fixtures, report tools, and qualification
  drivers with one simple inline-query execution benchmark. This is a benchmark
  reset for later redesign, not a new comparative performance qualification.

## Compatibility and downstream migration

- This intentionally breaking alpha advances predicate capability contract
  version to 2. SourcePredicateApplication and SourcePredicateCapabilities.Supports
  use SourcePredicatePatternMatch instead of SourcePredicateStringMatch. Rebuild
  datasource providers and distinguish LIKE from RLIKE before reading
  match-specific fields. Unknown capability versions leave predicates residual.
- Execution semantics contract version 2 and affected Execution IR contracts
  capture revised behavior. Incompatible stored artifacts must be recompiled;
  interpretation budgets and generated shapes participate in compatibility.
- The alpha release policy deliberately skips the datasource ABI baseline checks
  for Schema and Plugins; this is not a claim of binary compatibility.
- Cloud and datasource consumers need their own dependency upgrades, provider
  rebuilds, and manual refresh where these language and interpretation changes
  affect their documentation. Those actions are deferred to their respective
  repositories; this release changes only Core.
