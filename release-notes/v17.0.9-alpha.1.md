# Musoq 17.0.9-alpha.1 - First-class enums, stable scalar reuse, and diagnostic coverage

This full-train alpha consolidates the first-class enum implementation, the
stability-aware execution optimizations, the specification/generated-code
coverage expansion, and the diagnostic campaign work accumulated since
`17.0.8-alpha.1`.

This release publishes:

- `Musoq.Parser`
- `Musoq.Plugins`
- `Musoq.Schema`
- `Musoq.Evaluator`
- `Musoq.Converter`

## Highlights

### First-class enum language and runtime support

- Added contextual query-local `enum` and `flags enum` declarations with
  explicit integral underlying types, explicit member values, trailing-comma
  support, scoped visibility, and structured parser/semantic diagnostics.
- Added portable schema descriptors for enum identity, members, underlying
  kinds, scalar values, native CLR enum normalization, and target ABI
  contracts. Reachable native enum metadata is query-scoped and fingerprinted;
  the implementation does not retain a process-wide CLR enum cache.
- Bound enum identities and members through semantic analysis, expression
  conversion, intrinsic operations, source planning, predicate conversion,
  and generated execution. Generated query rows and source predicates use
  typed integral carriers rather than enum objects or loop-time reflection.
- Added capability negotiation and deterministic accepted/residual partitioning
  for enum-aware datasource predicates, with explicit diagnostics when a
  source cannot honor the required contract.

### Stability-aware execution and scalar reuse

- Added shared stability analysis and source metadata for stable versus
  volatile columns, replayability, computed projections, and conservative
  fallback behavior. The stability contract is documented independently from
  this alpha's intentional datasource ABI break.
- Added independently configurable, default-on loop-invariant code motion and
  stability-aware scalar reuse across projections, predicates, aggregates,
  windows, joins, APPLY, UNPIVOT, correlated/recursive CTE payloads, and source
  probe keys.
- Hoisted values are ordinary eager Execution IR locals selected at the
  planner/Execution IR boundary. Generated hot loops do not add runtime cache
  dictionaries, initialization sentinels, stability checks, or reflection;
  volatile and semantically unsafe boundaries remain excluded.
- Added qualification baselines, BenchmarkDotNet matrices, generated shape
  checks, execution checks, and optimizer guardrails for stable, volatile, and
  no-candidate workloads.

### Specification coverage and diagnostic quality

- Expanded the generated-code corpus and coverage ledger across the
  implemented Core Language, TABLE/COUPLE, and Binary/Text specifications,
  including operators, predicates, subqueries, joins, aggregates, windows,
  set modifiers, descriptions, coercions, interpretation, settings, and
  composition.
- Consolidated the diagnostic campaign and its permanent regression inventory
  across lexical, literal, statement-order, type, symbol, source, runtime,
  interpretation, and cross-feature contracts.
- Improved actionable diagnostics and source-span fidelity through parsing,
  cloning, semantic binding, rewrites, and compilation, including numeric and
  base-literal boundaries, escapes, bracketed identifiers, CASE/EXISTS
  recovery, TABLE/COUPLE ordering, and structured error envelopes.

## Compatibility

- This is an intentionally breaking alpha release of the five-package Core
  train. `Musoq.Schema` and `Musoq.Plugins` remain the datasource ABI packages,
  but alpha publication does not promise binary or source compatibility with
  the preceding 17.x train. Downstream providers must rebuild against these
  packages and adopt the enum/source metadata contracts where required.
- The release packer explicitly skips the datasource ABI baseline validator for
  this alpha tag. Stable, preview, and beta releases retain the normal
  compatibility gate.
- Non-enum query semantics and the legacy source-transfer behavior remain
  available where the current provider and query contracts select them, but
  this alpha should be treated as an experimental contract update.
- No standalone target package is introduced; target implementations remain
  bundled through `Musoq.Converter`.
- No `Musoq.DataSources`, `Musoq.Cloud`, `Musoq.CLI`, or `Musoq.Website`
  repository changes are included in this release. CLI exposure and
  datasource enum decoding remain follow-up work after the Core packages are
  published.

## Manual impact

This is a Core parser, schema, evaluator, converter, target, and benchmark
release. It does not change CLI commands, service behavior, supported tool
endpoints, MCP resources, or installer behavior. The Cloud-owned development
CLI manual applicability audit is run in check-only mode as part of release
verification; no manual update is expected.
