# Musoq 17.0.2-alpha.1 - Portable Execution Architecture

This full-train alpha introduces the portable execution architecture that prepares Musoq for future JavaScript, WASM, Python, and bytecode targets while preserving the current CSharpClr execution behavior.

This prerelease is for:

- `Musoq.Parser`
- `Musoq.Plugins`
- `Musoq.Schema`
- `Musoq.Evaluator`
- `Musoq.Converter`

## Highlights

- Added portable Execution IR descriptors for types, callables, literals, operations, semantics, and runtime host ABI requirements.
- Added target capability validation, deterministic readiness reports, structured diagnostics, target-aware cache semantics, and portable subset conformance tests.
- Kept CSharpClr as the only production target. No public target selector, export API, or third-party target SPI is introduced in this alpha.
- Kept the target architecture as separate internal assemblies and bundles those assemblies with `Musoq.Converter` so consumers do not restore unsupported `Musoq.Targets.*` packages.
- Added package-content and consumer smoke validation for the bundled target implementation, symbols, repository metadata, and clean restore graph.

## Compatibility

High-level Musoq query compilation, typed execution, inspection, compiled artifacts, diagnostics, and profiling APIs remain compatible with the CSharpClr runtime.

The public-looking Execution IR surface intentionally changed: portable type and callable descriptors, canonical constants, operation identifiers, and explicit semantics contracts replace CLR `Type`, `MethodInfo`, and arbitrary object payloads. Consumers that depended directly on those internal execution model classes must adapt to the new portable contracts.
