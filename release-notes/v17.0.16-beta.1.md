# Musoq 17.0.16-beta.1

This beta publishes seven aligned .NET 10 packages: Musoq.Parser,
Musoq.Plugins, Musoq.Schema, Musoq.Evaluator, Musoq.Converter,
Musoq.Formatter, and Musoq.Benchmarks.Scenarios. Upgrade engine packages together.

## Datasource diagnostics

The beta carries forward the 17.0.16-alpha.1 datasource diagnostics APIs.
Providers can describe recognized failures with DataSourceDiagnostic and
DataSourceException. Core preserves their public reports as MQ7020 through
discovery, planning, construction, row collection, deferred enumeration, and
cleanup, while keeping arbitrary inner exception text private.

Providers can report non-throwing warnings through
SourceExecutionContext.ReportWarning. Hosts collect MQ5027 diagnostics through
TypedQueryRunOptions.DataSourceWarnings, with per-execution isolation,
deduplication, bounded retention, and suppression reporting. See the
[provider and host guide](../docs/datasource-diagnostics.md).

## Changes since alpha.1

Evaluator tests are organized into focused projects with shared typed fixtures.
Filesystem fixtures use isolated task directories, and generated-code sample
discovery locates the repository independently of the process working directory.
A shared type-hint-cache test now avoids a parallel cache-clear race; the cache
field is exposed internally for typed test access without changing public APIs
or runtime cache behavior. Incremental-rename tests now materialize and dispose
their deferred result tables so batched compilation cleanup can complete.

Release packaging and publication use .artifacts output paths. Package manifests
contain filenames so artifacts can move between CI jobs, and hidden-directory
uploads explicitly include package output. Evaluator and Converter bundle target
assemblies, documentation, and symbols from their actual build output directory,
preventing stale files from a different output layout from entering packages.
Repository guidance has been consolidated, and documentation adds an expanded
SQL language tour and runnable
SQLite page/table interpretation examples.

## Compatibility and downstream work

This release introduces no new public API changes relative to 17.0.16-alpha.1.
Unlike alpha packing, beta packing requires the Schema and Plugins datasource
binary compatibility gate against the greatest published lower same-major
version, currently 17.0.16-alpha.1. Publication is conditional on that gate
passing; it does not certify compatibility across every earlier experimental
alpha boundary. Recompile persisted query artifacts when upgrading the engine.

Provider adoption of diagnostics, downstream dependency upgrades, Cloud
API/streaming presentation, CLI/browser guidance, and Cloud-owned manual
projections remain separate work. This Core release does not modify or build
sibling repositories.

## Qualification and publication

Local qualification passed release-script and tag/version validation, a Release
solution build with zero warnings and errors, and 30,453 tests across 17 projects
with zero failures and four intentional snapshot-refresh skips. Online packing
passed the Schema and Plugins binary compatibility checks against
17.0.16-alpha.1. All fourteen package/symbol archives were inspected, including
exact DLL, XML documentation, and PDB equality with the qualified build.
Output-layout and missing-symbol regressions cover the shared packaging target.
Commands, TRX results, manifests, hashes, and the earlier unsuccessful diagnostic
run are retained separately in the release qualification evidence.

Linux and Windows push CI must succeed for the exact release-branch commit before
the annotated tag v17.0.16-beta.1 is pushed. Completion requires a successful
tag-triggered Publish workflow, the GitHub prerelease's fourteen package assets,
matching package identities and payloads, and exact NuGet availability for all
seven packages. The verified release is then merged into master without
rewriting its commits, followed by Linux and Windows CI on the resulting commit.
