# Musoq 17.0.11-alpha.1 - structured inputs, string-match specialization, and runtime stability

This full-train alpha publishes the typed structured-datasource contract, specialized LIKE/RLIKE execution, Execution IR and Host ABI version 8, and a runtime-stability workaround for struct-key window sorting.

This release publishes:

- `Musoq.Parser`
- `Musoq.Plugins`
- `Musoq.Schema`
- `Musoq.Evaluator`
- `Musoq.Converter`

## Highlights

### Structured datasource inputs

- Added typed structured inputs for datasource parameters, `let` declarations, records, arrays, nested values, and direct CTE arguments.
- Preserved field presence separately from explicit null values so declared defaults, inferred values, and omitted fields have deterministic behavior.
- Added typed source registration, structural overload selection, CTE input storage semantics, ownership/lifecycle tracking, source metrics, strict limits, and actionable diagnostics.
- Added the structured-input example datasource, query corpus, invalid cases, and execution-mode coverage for host dictionaries, correlated calls, coupled sources, grouped/distinct/set/paged CTE inputs, and mutable ownership boundaries.

### LIKE/RLIKE execution and generated code

- Added planner and Execution IR strategy selection for literal, prepared, and dynamic LIKE/RLIKE patterns.
- Specialized stable patterns and retained BCL-managed semantics for culture-sensitive, Unicode, wildcard, and regex behavior.
- Added bounded matcher caching, APPLY-aware lowering, and generated-code shape coverage. LIKE/RLIKE remains evaluator residual execution rather than datasource pushdown.

### Execution IR and Host ABI

- Advanced the portable Execution IR and target-host contract to ABI version 8 for the new string-match and structured-input execution metadata.
- Kept strategy decisions in planning and Execution IR while the C# target renders the selected executable metadata faithfully.
- `Musoq.Targets.CSharpClr` remains bundled inside `Musoq.Converter`; it is not published as a standalone package.

### Runtime stability

- Replaced the pooled struct-key window-sort buffer with a regular array in the evaluator to avoid a .NET runtime crash in the affected window-sorting path.
- This is an intentional temporary stability workaround: it may increase allocations and reduce performance until safe pooling can be reintroduced.
- Hardened the release qualification paths for offset-bearing timestamps, blocking concurrent-run tests, and Unicode LIKE fallback matching. The changes keep CI validation independent of the host time zone and thread-pool pressure, and use a non-backtracking matcher for Unicode fallback patterns while retaining the existing bounded fallback for oversized expressions.

## Compatibility

- This is an intentionally breaking alpha release of the five-package Core train. `Musoq.Schema` and `Musoq.Plugins` are datasource ABI packages, but this alpha does not promise binary or source compatibility with the preceding 17.x train.
- Downstream datasource providers must rebuild against the complete `17.0.11-alpha.1` train and adopt the structured-input and ABI v8 contracts where applicable.
- The release packer intentionally skips the datasource ABI baseline validator for the alpha packages. Stable, preview, and beta releases retain the normal compatibility gate.
- No `Musoq.DataSources`, `Musoq.Cloud`, `Musoq.CLI`, or `Musoq.Website` changes are included.

## Manual impact

This is a Core parser, schema, evaluator, converter, and target release. It does not change CLI commands, service behavior, supported tool endpoints, MCP resources, or installer behavior. The Cloud-owned development CLI manual is checked in read-only mode; sibling Website and CLI checkouts are not modified.
