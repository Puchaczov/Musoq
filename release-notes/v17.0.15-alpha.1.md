# Musoq 17.0.15-alpha.1

This alpha publishes seven aligned .NET 10 packages: Musoq.Parser,
Musoq.Formatter, Musoq.Plugins, Musoq.Schema, Musoq.Evaluator, Musoq.Converter,
and Musoq.Benchmarks.Scenarios. Upgrade the engine packages together.

## Source-preserving SQL formatting

- Introduce the independent parser-only Musoq.Formatter package with the stateless
  MusoqFormatter.Format API, immutable formatting options/results, and original-input
  diagnostics. Defaults use four spaces, uppercase structural keywords, a
  100-character target width, and preserved line endings with LF fallback.
- Format complete queries and scripts, including interpretation schemas, CTEs,
  joins/APPLY, windows, structured values, parameters, and utility statements.
  Preserve identifiers, literals, explicit syntax, and comment contents; invalid
  scripts return diagnostics without partial output. CLI/Cloud integration remains
  separate work. See [formatter documentation](../docs/formatter.md).
- Add Parser.ParseSyntax and immutable token/trivia/source regions before execution
  AST normalization. Retain the ILexer interface and ordinary parsing entry points,
  with regressions for lookahead, qualified names, trivia, and contextual keywords.
- Verify preservation using typed AST projections and test-only Roslyn audits,
  dependency checks, mutation tests, specification fixtures, and generated cases.
  Production formatting does not depend on execution, providers, or Roslyn.

## Query execution and allocations

- Cache successful regex matching and validation without sharing mutable parser
  state or losing contextual failure diagnostics.
- Traverse scalar arrays/lists directly through APPLY WITH ORDINALITY, retaining
  single-pass enumeration, disposal, cancellation, outer-row presence, and nulls.
- Reuse terminal sort/projection buffers only with proven exclusive ownership,
  retaining stable ties, typed results, and conservative fallback paths.
- Remove capturing delegates from tolerant parsing and prune dead intermediate
  carriers while preserving argument evaluation, parser accounting, effects,
  hidden dependencies, and materialization boundaries.
- Add semantic, generated-code, ownership, concurrency, and effectful-pruning
  regression coverage. Remove unused code and obsolete renderer/test helpers.

Historical native Windows benchmark comparisons at 100,000 inputs recorded large
allocation reductions for scalar APPLY, collection/pivot, and regex-capture cases,
with improvements also observed for wide projections, windows, and packet pipelines.
These are workload-specific prior measurements, not new release benchmarks, peak
memory measurements, or a whole-engine speed guarantee. Compilation and fixtures
were outside execution timing; flagged timing comparisons received paired repeats.
Recursive chunk decoding retains its quadratic copying stress behavior.

## Reusable benchmark workloads and release tooling

- Publish Musoq.Benchmarks.Scenarios with deterministic typed fixtures and SQL
  workloads for use by engine and host measurements. Include relational, analytical,
  interpretation, and composed pipelines with result expectations.
- Add reproducible Official/Local campaigns, provenance, integrity verification,
  recovery receipts, and retained engine-v3 history and generated-code samples.
  Bound standard-size join workloads, widen packet totals, and apply scenario
  recursion and structural budgets. See [benchmark guidance](../benchmarks/README.md).
- Remove package-smoke scripts, metadata, tests, and CI/publication consumers.
  Ordinary unit tests, release-script checks, packaging, exact-SHA CI qualification,
  and external publication verification remain required.

## Compatibility and downstream work

This is an experimental alpha. The packer explicitly skips the previous published
Schema/Plugins datasource ABI baseline for alpha versions; binary compatibility
with previous providers is not certified. Rebuild and qualify downstream providers
against this aligned train, and recompile stored query artifacts when upgrading.
The parser gains source-capture APIs; the formatter and benchmark-scenario packages
are new. No public provider contract expansion is introduced for these optimizations.

Core documentation is updated here. Cloud CLI formatter integration, downstream
package upgrades, datasource integration qualification, and any Cloud-owned manual
refresh remain separate work; this release does not change sibling repositories.

## Qualification and publication

Qualification applies to the exact committed release candidate: focused formatter,
parser, and affected execution regressions; a warning-clean Release solution build;
the full Release solution test suite; release-script and tag validation; and seven
package/symbol pairs packed into a fresh directory. Package consumers and benchmarks
are not part of this release qualification. Results and skips are recorded in the
release evidence directory and final publication report rather than predicted here.

Before publication, both Linux and Windows push CI must succeed for that exact SHA.
The annotated tag v17.0.15-alpha.1 then triggers Publish. Completion additionally
requires the GitHub prerelease's fourteen package assets and the exact version of
all seven packages in NuGet, including downloaded identity/payload verification.
Only after these checks does the release branch merge into master.
