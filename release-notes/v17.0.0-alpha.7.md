# Musoq 17.0.0-alpha.7 - Runtime V2 Architecture Consolidation

This alpha release consolidates the runtime-v2 planning, lowering, rendering, and release pipeline work into a single full-train prerelease. The focus is architectural stability: explicit stage artifacts, clearer optimizer ownership, typed renderer state, extracted lowering models, and broader guardrail coverage around the runtime-v2 execution path.

This is a full-train prerelease for:

- `Musoq.Parser`
- `Musoq.Plugins`
- `Musoq.Schema`
- `Musoq.Evaluator`
- `Musoq.Converter`

## Highlights

- Added a typed build artifact store and stage-specific pipeline results for metadata, planning, rendering, execution, and compilation handoffs.
- Split logical, physical, execution, and codegen optimization responsibilities into dedicated pass groups, sessions, state, and fact objects.
- Introduced planning facts and shape resolution APIs used to pass row shape, physical node identity, and execution strategy data between planning and execution lowering.
- Extracted runtime-v2 lowering models and coordinators for aggregates, windows, CTEs, joins, post-operations, projections, applies, set operations, and outer-apply null substitution.
- Reworked execution C# rendering around explicit render contexts and render sessions, including node registry dispatch, typed sink rendering, and removal of renderer-wide mutable state.
- Added Roslyn and interpreter runtime seams for assembly loading, metadata reference caching, compilation creation, and runtime reference resolution.
- Extracted semantic binding and validation services for expressions, methods, result shapes, column properties, source binding, set operators, subqueries, and diagnostics.
- Added parser node traversal registry coverage so traversal behavior is centralized and covered by tests.
- Fixed aggregate filter handling across generic aggregate calls, wildcard aggregates, pivot measure lowering, scalar subquery aggregate classification, and structural aggregate identities.
- Expanded evaluator, parser, renderer, planning, package, and architecture guardrail coverage for runtime-v2 maintainability and release safety.

## Compatibility

This alpha keeps the package train on the `17.0.0-alpha` channel. The release is primarily internal architecture and correctness work; public package identities and the existing full-train release process are unchanged.
