# Musoq Core Engine 17.0.20

Stable patch release of seven aligned .NET 10 packages: Musoq.Parser,
Musoq.Plugins, Musoq.Schema, Musoq.Evaluator, Musoq.Converter, Musoq.Formatter,
and Musoq.Benchmarks.Scenarios. Upgrade engine packages together.

## Query compilation fixes

- Preserve original typed grouping keys through ORDER BY and paging when the
  selected output formats or omits those keys. Numeric ordering remains numeric,
  and hidden sort fields do not appear in public results.
- Validate interpreted collection fields against their active lexical carrier
  when inner and outer queries reuse an alias across CTEs and UNION branches.
  Missing or incompatible field access strategies still fail validation.
- Keep intermediate set-operation results in scope across generated query phase
  blocks, including three aggregate UNION branches over a CTE.
- Resolve composite JOIN and APPLY source identities before visiting the right
  source, fixing interpretation combined with scalar COUNT subqueries.
- Preserve MQ3018 for nullable integer indexes, including cases previously
  masked by an unrelated compiler failure. Coalesced nonnullable indexes continue
  to work.

The regressions use reduced, typed in-memory fixtures. Coverage includes 93
query reproduction/control cases, nested carrier validation, semantic compilation,
and structured-input datasource results and construction behavior. Only two
intentional generated-code snapshots change for the phase declaration fix.

## Compatibility and downstream impact

Datasource public contracts and plugin APIs remain unchanged. Two frozen provider
DLLs execute without recompilation against the corrected engine, preserving
control column names/types and complete expected rows. Unchanged provider source
also builds against the corrected engine. Stable packing validates Musoq.Schema
and Musoq.Plugins against the greatest published lower same-major ABI baseline.

Execution IR, host ABI and persisted-query package format versions are unchanged.
Recompile persisted queries affected by the corrected bindings or ordering to
receive these fixes. Downstream hosts can update their aligned engine packages
to 17.0.20 through their own qualification and release process. No datasource
migration or new CLI syntax is required; Core publication does not modify
downstream repositories or their documentation projections.

## Qualification

The implementation passed a Release solution build with zero warnings/errors,
31,244 tests with four existing ignored refresh utilities, formatting, generated
sample preservation, and unchanged-provider binary checks before release metadata
was added. Publication additionally requires qualification of the exact release
commit: release-script/tag checks, restore, Release build, the full suite,
seven-package packing with datasource ABI validation, and successful Linux/Windows
release-branch push CI. After publication, all selected GitHub package/symbol
assets and seven exact NuGet package versions and payloads are verified.

Local performance comparisons retain every raw attempt. Apparent binary and
warm-compilation slowdowns in noisy Short runs reversed in longer Default
comparisons, with effectively unchanged allocations. These timings do not
establish a speedup. No new Official benchmark campaign or README chart refresh
is included.
