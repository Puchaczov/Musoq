# Musoq 17.0.4-alpha.3 - Public DynamicObject generated execution

This full-train alpha fixes generated-query binding for public `DynamicObject` datasource roots while preserving the datasource source-row contract. Runtime-defined member names are now resolved at the engine boundary instead of being rejected as unsupported custom dynamic types.

This release publishes:

- `Musoq.Parser`
- `Musoq.Plugins`
- `Musoq.Schema`
- `Musoq.Evaluator`
- `Musoq.Converter`

## Highlights

- Public, referenceable `DynamicObject` roots can be requested through their concrete CLR type in generated execution, including constant queries that do not read any columns.
- Schema-advertised runtime members are emitted as immediate-receiver DLR `GetMember` operations and immediately cast to schema-inferred types. Static CLR properties remain ordinary static member access.
- Nested public `DynamicObject` values support canonical case-insensitive schema names, default and explicit type hints, SQL null propagation, null-guarded leaves, typed comparisons, joins, and statically bound library calls.
- Runtime member paths are reused within a row when shared by predicates and projections; projection-only values are not read for rejected rows, and no per-row adapter, reflection, dictionary conversion, or nested helper is generated.

## Compatibility boundary

- The existing datasource source-row contract remains unchanged; datasources continue to advertise their concrete row type through `GetRowSource<T>`.
- Support is intentionally limited to publicly referenceable `DynamicObject` types and the existing dictionary/`ExpandoObject` contracts.
- Private or inaccessible dynamic roots, arbitrary `IDynamicMetaObjectProvider` implementations, and inaccessible advertised result types continue to fail with MQ3084.
- A schema-advertised member returning `true` with `null` is SQL null. `TryGetMember` returning `false` for an advertised member remains a datasource contract failure.

## Review artifacts and verification

- Added generated-code samples Q231–Q234 covering constant roots, mixed static/runtime filtering and projection, nullable nested values, and runtime join keys passed to static methods.
- Added runtime-dynamic regression fixtures with exact concrete `GetRowSource<T>` assertions, DLR-only member binding checks, read counters, negative-policy coverage, and alternate-schema warm-cache executions.
- Added cold compilation, cache-hit compilation, generated hot execution, and handwritten DLR hot execution benchmark cohorts.
- Release verification covers the full Release solution, generated-code corpus, package validation, and clean consumer smoke tests for all five packages.
