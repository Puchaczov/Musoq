# Musoq 17.0.10-alpha.1 - Compile-time cancellation and cache ownership

This full-train alpha hardens cooperative cancellation across the Core
compile-time pipeline and keeps transient invocation state out of reusable
semantic, execution, and artifact state.

This release publishes:

- `Musoq.Parser`
- `Musoq.Plugins`
- `Musoq.Schema`
- `Musoq.Evaluator`
- `Musoq.Converter`

`Musoq.Targets.CSharpClr` is bundled through `Musoq.Converter` and is not a
standalone package.

## Highlights

### Compile-time cancellation

- Added final `CancellationToken` overloads for Core compilation, analysis,
  diagnostics, execution, typed execution, artifact storage/loading,
  inspection, profiling, plan generation, and asynchronous compilation APIs.
- Propagated invocation cancellation through metadata discovery, runtime
  settings resolution, source planning, query analysis, transformation,
  Execution IR lowering, target rendering, Roslyn emission, artifact
  validation, packaging, loading, activation, and generated-code inspection.
- Preserved the original `OperationCanceledException` instead of converting
  cancellation into a compiler diagnostic.
- Kept existing overloads and legacy target/compiler contracts operational by
  defaulting them to `CancellationToken.None`.

### Cache and resource ownership

- Made semantic-template, execution-compilation, and canonical-artifact cache
  operations cancellation-safe with cancellable flight waiters,
  prepare/commit/discard publication, cache-hit rebinding, and removal of
  transient invocation tokens from reusable state.
- Added reader leases and retirement-aware disposal so cached executable
  artifacts are released exactly once and only after active readers finish.
- Hardened runnable, compiled-query, artifact, assembly-load-context, and
  temporary-file ownership when cancellation occurs after resource creation.

### Target and Schema contracts

- Added cancellation-aware build, rendering, finalization, artifact-package,
  C# emission, and rendered-query inspection contexts.
- Added cancellation state to transient Schema source-planning and
  runtime-settings resolution requests without including invocation tokens in
  cache keys, semantic artifacts, artifact metadata, or portable contracts.
- Retained the legacy `CompilationContextManager` constructor while adding
  cancellation-aware construction, preserving binary compatibility for
  existing bundled-target consumers.

### Documentation

- Added the compile-time cancellation contract to the README and dedicated
  documentation, including cooperative-provider limitations and compatibility
  behavior.
- Corrected the ASOF JOIN reference to the diagnostic contract and catalog.

## Compatibility and train scope

This is a full five-package Core alpha release because the new cancellation
contract crosses the `Musoq.Schema` -> `Musoq.Evaluator` -> `Musoq.Converter`
dependency chain, and `Musoq.Targets.CSharpClr` is bundled inside Converter.
Parser and Plugins have no production implementation changes, but are included
to keep the Core train version-aligned.

The Schema changes are additive and transient cancellation tokens are not part
of reusable artifact or cache identity. The legacy public
`CompilationContextManager(CSharpCompilation, EvaluatorRuntimeEnvironment?)`
constructor is retained. Alpha datasource ABI validation remains governed by
the repository's explicit experimental alpha policy; downstream datasource
providers should nevertheless rebuild and qualify against this complete Core
train.

## Manual impact

This is a Core engine release. It does not change CLI commands, service
behavior, supported tool endpoints, MCP resources, or installer behavior; no
CLI manual update is expected.
