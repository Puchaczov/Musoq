# Musoq 17.0.16-alpha.1

This alpha publishes seven aligned .NET 10 packages: Musoq.Parser,
Musoq.Plugins, Musoq.Schema, Musoq.Evaluator, Musoq.Converter,
Musoq.Formatter, and Musoq.Benchmarks.Scenarios. Upgrade engine packages together.

## Public datasource errors

Providers can describe recognized problems with `DataSourceDiagnostic` and throw
`DataSourceException`, retaining an optional private inner exception. Reports carry
an extensible provider code and category, public message, suggested fixes, safe
details, optional argument/input location, and advisory retry guidance. Shared
failure kinds cover input, configuration, access, missing resources, rate limits,
availability, timeouts, and provider defects.

Core preserves these reports as MQ7020 through discovery, planning, construction,
synchronous/asynchronous row collection, query-scoped construction, background
producers, deferred enumeration, and cleanup. Source identity and operation travel
with the public envelope. Datasource input positions remain separate from SQL
locations. Existing specific diagnostics, cancellation, and independent aggregate
failures retain their handling. An error after rows have been emitted still fails
execution; hosts must identify streamed rows as partial results.

## Non-throwing warnings

Metadata and planning return copied diagnostic collections. Runtime providers call
`SourceExecutionContext.ReportWarning` without interrupting row production. Hosts
can supply a fresh `DataSourceWarningCollector` through
`TypedQueryRunOptions.DataSourceWarnings` and read standard MQ5027 diagnostics
after enumeration, including after a failure.

Collectors isolate executions, support concurrent producers and deferred results,
deduplicate identical reports per source, and retain 100 distinct warnings.
Repeated retained reports carry occurrence counts; additional reports increment a
suppression count with a summary diagnostic. Core does not retry queries or decide
whether a provider should tolerate malformed input.

## Public and private content

Provider-authored messages and fields are explicitly public. Core bounds and
escapes text and redacts sensitive keyed details and identified path values.
Providers must not copy raw SDK messages, credentials, record contents, or response
bodies into public fields. Arbitrary inner exception text is not exposed as public
guidance. See the [provider and host guide](../docs/datasource-diagnostics.md).

Ordinary row reads do not format diagnostics. Focused allocation checks cover the
disabled reporting path and reuse of bound source reporters; these checks do not
claim a whole-engine throughput improvement.

## Compatibility and downstream work

This experimental alpha expands the public datasource diagnostic and execution
context APIs and changes generated source bindings. The alpha packer intentionally
skips the published Schema/Plugins datasource ABI baseline; binary compatibility
with previous providers is not certified. Rebuild and qualify downstream providers
against the aligned train, and recompile persisted query artifacts. This is the
intentional alpha compatibility boundary; no compatibility shim is introduced.

Existing providers can keep their current error and warning behavior until they
adopt the new API. Provider-specific classification and filesystem path validation
belong to the subsequent DataSources section. Cloud API/streaming presentation,
CLI/browser guidance, dependency upgrades, and Cloud-owned manual refresh remain
deferred. This Core release does not modify or build sibling repositories.

## Qualification and publication

Implementation qualification passed a warning-clean Release solution build and
30,444 tests with zero failures and four intentional skips. Following test-only
cleanup, the complete Schema suite passed 954 tests. The release candidate receives
its own build, full-suite run, release-script/tag validation, and fresh packing of
all seven package/symbol pairs. Exact receipts and any skips are retained in the
release evidence; implementation receipts do not substitute for release gates.

Before publication, Linux and Windows push CI must succeed for the exact release
commit. The annotated tag `v17.0.16-alpha.1` then starts Publish. Completion requires
the GitHub prerelease's fourteen package assets, matching package identities and
payloads, and exact NuGet availability for all seven packages. The release metadata
commit remains separate from the reviewed implementation commit. Integration into
the default branch follows successful publication and its verification.
