# Musoq 17.0.2-alpha.3 - Correlated Subquery Execution

This full-train alpha adds set-based execution for supported correlated subqueries across the Musoq runtime-v2 pipeline.

This prerelease is for:

- `Musoq.Parser`
- `Musoq.Plugins`
- `Musoq.Schema`
- `Musoq.Evaluator`
- `Musoq.Converter`

## Highlights

- Added decorrelation for `IN`, `EXISTS`, `NOT IN`, `NOT EXISTS`, `ANY`, `SOME`, `ALL`, scalar subqueries, and correlated `CROSS APPLY` shapes.
- Added hash and indexed range strategies for equality, composite-key, and one-bounded-range correlation, including semi, anti-semi, mark, and scalar-single joins.
- Added per-key scalar `ORDER BY`/`SKIP`/`TAKE`, `DISTINCT`, grouping, window/`QUALIFY`, and supported set-operator shaping without hidden per-row execution.
- Added typed correlated scalar-result carriers, empty-result handling, scalar-cardinality checks, null-aware correlation behavior, CTE sidecar indexes, and bounded range-frame resolution.
- Added generated-code snapshots, integration and performance coverage, and benchmark report comparison tooling.
- `Musoq.Schema` and `Musoq.Plugins` remain protected by same-major datasource ABI validation during packaging.

## Compatibility

The existing CSharpClr compilation and execution APIs remain unchanged. Unsupported correlation shapes are rejected with `MQ2024_InvalidSubquery` rather than silently selecting nested-loop or per-row `APPLY` execution.

Release verification passed with 15,564 tests and 4 intentional refresh tests skipped.
