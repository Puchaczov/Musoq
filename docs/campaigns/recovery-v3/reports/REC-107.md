# REC-107 — Truncation and incomplete-query prefix coverage

## Outcome

REC-107 uses a two-revision frozen prefix matrix. Revision 1 observed 48
registered cases and exposed three mutation-oracle errors; it was preserved
unchanged. Two independent read-only campaign reviewers approved the explicit
oracle correction. Revision 2 corrected those three mutations, froze a new
48-case contract, and replayed all 48 cases successfully. No production
parser change was justified or made.

The final matrix contains 40 incomplete prefixes and eight valid ordinary
controls across eight grammar families. Every seed parsed without diagnostics;
every invalid revision-2 candidate produced exactly one Parse/Query/Error
diagnostic, and every control remained valid. The candidate assertions also
check diagnostic metadata, bounded spans, guidance and absence of a semantic
or binder root replacing the parse root.

The matrix includes EOF after required clauses and operands, open function
delimiters, required aliases, trailing separators, compound-keyword boundaries
(`INNER JOIN`, `GROUP BY`, `ORDER BY`, `NULLS`, `WITH`, and `BETWEEN`), CTE
boundaries, and declaration prefixes. Optional SKIP/TAKE clause removal is
represented as a valid control in the revision-1 observation and required
count removal is tested by the revision-2 candidates.

## Oracle correction

Revision 1 was not silently edited after observation. Its behavior artifact
records 45 exact matches and three mismatches:

1. REC-107-P02 removed `where 1` while retaining `= 1`, so the observed form
   was `MQ2001_UnexpectedToken`, not the declared EOF-after-operand prefix.
2. REC-107-O04 removed the complete optional `skip 2` clause, so the result
   was valid ordinary syntax rather than an invalid missing-count form.
3. REC-107-O05 had the same issue for `take 2`.

Revision 2 preserves the original cases and uses new candidate-version IDs:
P02 truncates after `where 1 =`, while O04/O05 retain SKIP/TAKE and remove
only the required count. Existing parser coverage independently confirms
`MQ2020_MissingOperand` for an expression ending after `=` and
`MQ2038_InvalidSliceCount` for a missing slice count. Both read-only reviewers
approved the correction; neither found a production defect.
