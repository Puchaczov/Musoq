# REC-110 — Incremental renames and stale scope references

## Outcome

REC-110 completed with the final revision-5 diagnostic matrix. It contains 48
cases across eight families: 39 invalid copied-and-edited queries and 9 valid
ordinary controls. Every invalid candidate reaches exactly one Bind diagnostic
with the frozen code, token, scope and guidance contract; the controls execute
without changing scope resolution.

The immutable revision-1 through revision-4 records preserve the earlier
observations and oracle corrections. Revision 5 re-freezes the same 48-case
candidate payload after adding permanent grouped-diagnostic regression tests
outside the matrix.

## Root cause and repair

The first B02 observation showed an unresolved `GROUP BY` consumer producing
both `MQ3012_NonAggregateInSelect` and the root `MQ3001_UnknownColumn`. The
semantic recovery path needed to suppress only the dependent projection
cascade, not independent sibling roots. A broad overlap-only implementation
was rejected by independent review because it missed qualified alias identity
and could hide a projection from another source.

The final repair in
`SemanticDiagnosticReporter.cs` and `SemanticQueryValidationService.cs`:

- reconstructs a qualified GROUP BY span from parser-node descendants when a
  `DotNode` has no direct span;
- associates an unresolved GROUP BY diagnostic with a projection only when its
  terminal or structured candidate name matches;
- requires compatible source-qualifier sets for known-column repairs, retaining
  independent `a.Country` when the unresolved key is `b.Countr`;
- preserves unknown-alias cascade suppression where source identity is itself
  unavailable; and
- never synthesizes aliases or imports repair candidates from another query
  block.

The permanent controls cover the unknown-alias cascade, independent unknown
columns, mixed grouped keys, known-alias unknown columns, and the symmetric
cross-source qualified case.
