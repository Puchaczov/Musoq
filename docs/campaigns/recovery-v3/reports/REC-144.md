## Scope boundary

This scope builds a capability-boundary harness for future repair studies. A
fake actor receives a small public task envelope and a gateway that exposes
only bounded discovery and semantic submission. Filesystem, repository,
history, process, private-judge and destructive operations are not exposed.
This is a same-process simulation, not an operating-system sandbox and not a
claim that an ordinary subagent is automatically blind.

## Harness contract

The public envelope contains only `taskId`, `taskPrompt`, `malformedQuery`,
`deliveredDiagnostic`, `invariant`, `allowedOutcomes` and `mustExecute`.
Fixture identity, split identity, parent reasoning, expected mutations and
gold-answer fields are absent. The gateway permits only the bounded discovery
names `schema_shape`, `source_methods` and `runtime_settings_metadata`, plus
semantic submission.

Denied requests are retained as contamination attempts and exclude a run from
scoring. The harness separately classifies over-budget runs, malformed answers,
no submission and semantic judge failure. A semantically correct submission
is judged from result facts and private row fingerprints; the repaired SQL
spelling is not returned in the result record or used by the judge.

The manifest
`docs/campaigns/recovery-v3/cases/REC-144-simulated-actors.json` records five
fake actor identities, exact instructions, capabilities and intended checks.
All construction runs are marked `simulated_construction`; no live model,
human participant or empirical score is produced.

## Boundaries and findings

No production engine change was required. The fake actors and semantic judge
are construction tests only. In a live study, the gateway must be backed by a
real process/container access boundary; a changed working directory alone is
insufficient. Contaminated attempts must remain visible and excluded from any
future score.
