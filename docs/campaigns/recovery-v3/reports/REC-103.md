# REC-103 — Native enum discovery and TABLE source planning

## Outcome

REC-103 passed. The final focused replay executed all 29 registered tests:
24/24 candidate cases, 4/4 validation controls, and 1/1 matrix check, with no
failures or skips. All 20 valid candidates executed through the intended typed
or dynamic runtime path. The frozen case contract and pre-observation manifest
verified successfully.

The first post-freeze replay passed 21 and failed 8. It was excluded from
candidate evidence. That replay exposed a real production boundary defect plus
fixture assertions: the semantic pipeline wrapped the supplied provider in
`TransitionSchemaProvider`, so exact native enum lookup searched only the
wrapper assembly and rejected a reachable provider enum. The final fix exposes
the inner provider for assembly traversal and keeps exact fully qualified,
enum-only matching. The metadata fixture also now supplies its typed table
contract and `QueryScopedRows|LogicalScalarReads` capabilities.

## Contract coverage

- Native typed rows covered `short` and `uint` enum carriers, nullable values,
  unknown representable values, flags, CTE, join and mixed ordinary-column
  paths.
- TABLE metadata covered exact fully qualified native enums, query-local enums,
  nullable lifting, modifiers, unknown type names and duplicate modifiers.
- Dynamic query-scoped rows remained primitive carriers (`short` and `uint`),
  retained frozen query-local descriptors, and did not expose boxed enum
  objects.
- The metadata provider captured columns without requesting object rows. The
  capability-negative case failed at Bind with
  `MQ3114_EnumSourceCapabilityRequired` and named the source/column contract.
- Invalid candidates produced one root diagnostic each: two
  `MQ3005_TypeMismatch`, one `MQ2012_InvalidSchemaDefinition`, and one
  `MQ3114_EnumSourceCapabilityRequired`, with no unexpected secondary errors.

The duplicate modifier case `REC-103-T07` emitted `MQ2012_InvalidSchemaDefinition`
at `Parse`. This is recorded as an observed parser-phase exception rather than
silently relabeled: the bound TABLE specification §7.1 classifies duplicate
read modifiers as parse-time, and the existing parser regression path covers
that behavior. The frozen case identity, query, diagnostic code and authority
snapshots were not changed; the other invalid candidates are bind-time.

No SeparatedValues plugin was assumed or used.
