# REC-125 — Diagnostic state reuse and deterministic ordering

## Status

The authoritative revision-3 contract is frozen and verified for 24 cases
across five families. The permanent state-reuse matrix passed all 6/6
methods, parser and evaluator diagnostic adjacency passed, and the Release
gate passed all 8/8 targets. No production defect was confirmed in this
scope; REC-125 is ready for its completion commit.

The supported boundary is sequential reuse of `QueryAnalyzer`,
`DiagnosticBag`, `DiagnosticContext` and immutable `Diagnostic` copies. The
contract does not claim concurrent sharing where the API does not support it.

## Oracle correction and findings

Revision 1 was frozen before observation and remains preserved. Its B06
nested-CTE declaration mutation exposed the intended `MQ3001_UnknownColumn`
root plus a derivative `MQ3027_InvalidExpressionType` output-shape diagnostic,
so the declared single-root observation was not isolated. Revision 2 retained
the nested scope but mutated the unique outer `p.Name` consumer to `p.Missing`.
The corrected observation passed with one B06 unknown-column root.

Revision 3 is an administrative evidence revision only: it changes the
fixture reference from the removed observation helper to the permanent
`CandidateMatrix_ShouldCoverFrozenContract` test. It does not change any
seed, mutation, expected diagnostic, authority or observed result.

No production finding was confirmed. The permanent matrix found no residual
error bag, counter, stale metadata, nondeterministic schema ordering, limit
suppression or structured-payload loss.
