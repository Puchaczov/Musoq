# REC-102 — Enum intrinsics, flags, NULL and unknown values

## Outcome

REC-102 passed its final focused replay and fresh whole-solution Release gate. No production defect was reproduced and no production code changed. The scope commit contains the evaluator regression fixture and campaign evidence.

## Contract and candidate coverage

- Authority: core sections 3.8, 18.4, 19.10 and 22.5; `docs/enums.md`; diagnostic catalog codes MQ3108 and MQ3111.
- Frozen pre-observation contract: 24 novel candidates in three families and 4 validation controls, matrix revision 1.
- Signature and type restrictions: 12/12 passed with one MQ3111 bind diagnostic and catalog guidance per invalid candidate. Coverage included arity, non-enum first arguments, non-flags enums, numeric masks and dynamic string masks.
- Flags and composite runtime: 6/6 passed. Declared single and composite masks, zero-mask any/all semantics, and exact declared composite naming were exercised.
- NULL and unknown runtime: 6/6 passed. Every intrinsic was exercised against nullable NULL and representable unknown carriers; NULL predicates returned false, unknown names/definedness remained negative, and enum metadata was retained.
- Candidate result: 24/24 passed, 24 clean, 0 duplicate, 0 metamorphic and 0 production fixes.

The final focused test executed all 29 tests: 24 candidates, 4 controls and 1 matrix check. Invalid candidates had one root MQ3111 diagnostic with guidance and no unexpected secondary diagnostics. Runtime observations included `HasAnyFlags(ReadWrite, zero-mask) == false`, `HasAllFlags(ReadWrite, zero-mask) == true`, `EnumName(ReadWrite) == ReadWrite`, NULL propagation, and unknown status carrier value `99` with enum metadata.

## Observation history

The first post-freeze replay ran all 29 registered tests but exposed two fixture assertion mismatches; its aggregate was excluded from candidate evidence. The authoritative contract states that a non-null zero-mask `HasAllFlags` is true, so the unknown-flags expected value was corrected from false to true. The nullable native status fixture also exposed `Nullable<short>` column metadata while preserving boxed `short` values, so the metadata control was corrected to the declared nullable carrier type. The frozen case identities, candidate queries and expectations were otherwise unchanged; no production code changed.

The corrected final replay passed all 29 tests, and all valid candidates executed through compilation and runtime. The frozen manifest and case contract verify successfully.
