# REC-132 — Typed and dynamic source-shape compatibility regressions

## Status

REC-132 is complete. The frozen 48-case matrix passed 48/48 on the final
replay, all corrected adjacent suites passed 63/63, and the authoritative
Release gate passed all 8/8 targets. One production finding was confirmed and
resolved: dynamic coupled ASOF right sources were rejected by Execution IR
even though the source contract permits ASOF joins over coupled aliases.

the typed cases are retained as a separate comparison and are not used as
proof of dynamic support.

## Initial observations and repair

The first two attempts were compile-only corrections and emitted no behavioral
results. The first behavioral replay passed 10/48. After fixture calibration,
r4 passed 28/48 and isolated the dynamic ASOF boundary: dynamic right-source
cases failed through MQ9001 with the underlying unsupported-shape reason, while
the calibrated typed expectations were corrected transparently.

REC-132-F01 was confirmed and resolved. `BuildAsOfJoinTable` previously
accepted only a source entity or table-row right source. It now materializes a
dynamic adapter right source into a generated-row candidate list before ASOF
index creation and probing, while preserving the source's generated row type.
The helper was placed in a dedicated partial file so the production hotspot
budget remains satisfied. The converter inspection and execution tests now
assert the supported dynamic plan and executable result.

The first authoritative Release gate was intentionally preserved as r1. It
failed only because two existing converter tests still expected the old
dynamic-ASOF rejection and the evaluator hotspot file had grown to 254 lines
against a 237-line budget. Those expectations and the file split were repaired;
the fresh r2 gate passed.
