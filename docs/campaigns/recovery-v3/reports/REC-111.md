# REC-111 — Competing schema, source, alias and member failures

## Outcome

REC-111 completed with the final revision-2 diagnostic matrix. It contains 48
cases across eight families: 39 invalid copied-and-edited queries and 9 valid
ordinary controls. Every invalid candidate asserts the exact ordered Bind
diagnostic envelope, valid source/query locations, expected token facts and
absence of forbidden dependent codes.

Revision 1 is preserved as the initial frozen observation. Its A03 mutation
caused `BasicSchemaProvider` to throw a provider `MethodResolutionException`
before the required diagnostic envelope. Revision 2 changes only A03 to a
known `Substring` callable with one argument, expecting
`MQ3087_InvalidCallableArity`; its correction is recorded and independently
approved in the oracle-correction artifact.

The matrix covers schema/source precedence, unknown aliases with plausible
chains, known-owner column/property roles, callable-root precedence, CTE and
derived query-block boundaries, exported names, and independent sibling
roots. It rejects a noisy cascade even when the intended code appears later in
the result.

## Root cause and repair

The initial observations showed three recovery defects. Unknown callable and
invalid-arity failures retained diagnostics from invalid arguments. An invalid
inner query could also leave an outer derived/CTE consumer diagnostic that
obscured the inner alias root. Finally, recovery had to preserve independent
column, alias and property siblings instead of applying a query-wide filter.

The final repair in `DiagnosticContext`, `DiagnosticRecovery`, and the
visitor source/query-state partials:

- removes only error diagnostics inside the failed callable argument span for
  `MQ3086_UnknownCallable` and `MQ3087_InvalidCallableArity`;
- preserves the established SQL Server-shaped `CONVERT(varchar, Population)`
  compatibility root (`MQ3001_UnknownColumn`), covered by P_MISC_07;
- records CTE values containing a recovery root and suppresses only dependent
  outer consumers of that recovered table;
- retains source-ordered independent sibling roots; and
- keeps the implementation within the existing visitor maintainability
  budgets by placing shared recovery traversal in a focused helper.
