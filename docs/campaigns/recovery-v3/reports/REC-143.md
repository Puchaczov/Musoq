## Scope boundary

This scope establishes a finite diagnostic-recovery task corpus without making
success depend on one gold SQL spelling. It records semantic task invariants,
repository-owned fixture identities, a leakage-resistant split identity, a
separate private-judge boundary and a held-out reservation state. It does not
run live repair actors, expose judge answers or claim empirical repair accuracy.

## Corpus and judge contract

The repair payload is
`docs/campaigns/recovery-v3/cases/REC-143-task-corpus.json`, containing 16
development tasks: two each in lexical, omissions, names, types,
grouping/windows, enum, TABLE/COUPLE and binary/text families. Each task has a
fixture path and test name; validation confirmed all 16 paths and all 16 test
names against repository-owned source files.

Each task requires columns, minimum row multiplicity, ordering, NULL policy,
failure policy and a bounded clarification contract. `mustExecute` is true for
every task. The judge rejects compile-only and empty-result observations before
checking semantic invariants, and execution success compares result facts and
private row fingerprints rather than repaired SQL spelling.

The split group is the tuple `(seedGroup, semanticFamily,
providerFixtureId)`, hashed by `sha256-group-v1`. The payload contains eight
development groups and eight explicit `holdout_reserved` groups with no
cross-partition leakage. Superficial query spelling does not change the group.

Private judge observations are produced by `build_private_judge` as a separate
`private_judge` object. Answer-bearing keys are forbidden in the repair
payload. The final holdout remains `reserved_until_freeze` with
`finalHoldoutCreated: false`; materialization requires compared build
identities and a frozen repair-prompt SHA-256. No held-out answer was exposed.

not a live study. The private judge contract is tested with repository-local
synthetic observations only; no actor, human participant, model score or
unverified recovery result is claimed. The full gate retains only the three
pre-existing generated-snapshot refresh skips.
