# REC-087 — Pre-register candidate expectations and outcome classes

Status: full gate passed; completion fields and commit pending.

## Scope and implementation

REC-087 adds tools/case_contract.py, a small standard-library helper for
freezing diagnostic candidate expectations before candidate observation. It
validates the required case fields, exact one-occurrence mutations, repository
fixture references, valid seed declarations, source citations and allowed
outcome/repair classes. It derives a root-cause/context/domain fingerprint that
does not include case IDs or identifier spellings.

The freeze command writes a non-replaceable pre-observation manifest. The
verify command recomputes the raw authority hashes, every case digest, mutation
result, fingerprint and aggregate payload digest. Changing an expected
diagnostic after freeze therefore fails verification. A case cannot add
observed diagnostics while its state is unobserved.

The registered cases are in
docs/campaigns/recovery-v3/cases/REC-087-pre-registered.json; the frozen
manifest is docs/campaigns/recovery-v3/evidence/REC-087-pre-observation-
manifest.json. They were frozen before the focused parser replay. The case
payload digest is

raw core specification hash is

All four seeds are declared valid and point to repository-owned parser/lexer
fixtures. The focused replay after freezing selected the four named existing
regression tests and passed 4/4. This validates the seed/boundary fixtures; it
does not claim that the new JSON file itself executes mutations or that an
engine result can replace its frozen oracle.

The valid cases are intentional false-positive controls: an unusual mutation
need not be invalid. The invalid case has one pre-registered root cause and
contracted diagnostic shape. Any eventual minimization must retain the
original mutated query and supply a minimized query together with evidence that
the fault and observation are unchanged. No candidate failure was minimized
in this harness-registration scope, so the four actual case records remain
pending_observation.
