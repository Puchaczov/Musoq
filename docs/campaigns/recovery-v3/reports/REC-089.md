# REC-089 — Independently verify catalog meaning and retired-code behavior

REC-089 completed its audit gate at the resolved engine baseline. The audit
kept the active code set dynamic, checked catalog meaning against an
independently authored specification oracle, and treated compatibility-only
identifiers as explainable metadata rather than trigger obligations.

## Independent catalog oracle

`tools/diagnostic_catalog_audit.py` reads only the current
`DiagnosticCode.cs` declarations, `specs/diagnostic-catalog.json`, the
recovery authority specification, and
`tools/rec089-independent-oracle.json`. It does not import or invoke
`DiagnosticDescriptorRegistry` or any descriptor factory.

The audit found 210 enum members and 210 catalog entries with identical
code/number pairs. The active inventory is derived at runtime; it does not
freeze a historical count or enum list. Five high-risk callable root causes
were checked against specification-authored facts: unknown source, unknown
callable, invalid arity, no matching overload, and ambiguous overload.

The intentionally wrong MQ3086 explanation control was rejected because it
removed the independently required `no scalar` root-cause fact. This remains
true even if a descriptor implementation and catalog copy were changed
together.

## Retired and compatibility-only identifiers

All 25 numeric values listed by the v17-to-v18 migration oracle were absent
from both the enum and catalog, including the compatibility-documentation-only
value 5009. The catalog compatibility identifiers MQ5020 and MQ5026 were
present, described as compatibility metadata, and explicitly state that the
current language version does not emit them.

No artificial trigger test was created for MQ5009, MQ5020, or MQ5026. The
focused set-operation tests instead verified current result-level ordering and
slicing behavior without either dormant warning, while the migration tests
verified that retired values are not registered or repurposed.

## Retained drift decisions

The independent audit confirmed both assigned historical drift records:

* DRIFT-001 remains explicit because the authority supports simple CASE while
  the current MQ2026 catalog explanation still says searched CASE only.
  MQ2028 and MQ2029 remain catalog entries, while the focused current parser
  behavior uses the generic MQ2001 root for the tested missing-ELSE recovery.
* DRIFT-002 remains explicit because section 18 says function names are
  case-sensitive while the window/function rules say function names are
  case-insensitive and underscore-insensitive. The set-order compatibility
  identifiers are separately explainable and non-emitting.

These are retained findings, not silently rewritten historical objectives and
not treated as a reason to fabricate legacy trigger cases.
