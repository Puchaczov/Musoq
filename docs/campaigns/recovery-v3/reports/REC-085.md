# REC-085 — Make the full test gate prove project completeness

Status: completed after the completion commit.

## Scope and change

REC-085 is the first engine-lane harness scope after the REC-084 baseline. The
selected solution is `src/dotnet/Musoq.sln`; the gate remains the repository's
restore, Release build, and unfiltered solution test sequence. The new
standard-library helper at
`docs/campaigns/recovery-v3/tools/full_gate.py` adds evidence checks around
that existing sequence rather than introducing another test orchestrator.

The helper now:

- discovers solution projects with `dotnet sln ... list`, identifies test
  projects from the test SDK, and records every target framework;
- snapshots a defined source payload before and after the build/test run;
- requires a non-incremental Release build and records each test assembly
  digest before testing;
- requires a fresh result directory and binds every TRX to exactly one
  discovered test assembly through its `TestMethod codeBase`/storage;
- verifies command exit codes, command log digests, result freshness,
  configuration, solution, no-build/no-restore test invocation, counters,
  execution timestamps, result uniqueness, and post-build artifact stability;
- reconciles skipped tests from explicit `UnitTestResult` outcomes and checks
  every skipped identity against a reasoned allowlist.

The existing checker self-tests were made independent of campaign progress by
using an explicit all-pending synthetic ledger fixture. No Musoq production
code or engine test was changed.

## Commands and review

The focused harness command was:

    python -m unittest discover -s docs/campaigns/recovery-v3/tools -p "test_*.py" -v

It passed 31 tests, including the 21 campaign-checker tests and 10 full-gate
tests. The discovery command was:

    python docs/campaigns/recovery-v3/tools/full_gate.py discover --solution src/dotnet/Musoq.sln

The full gate ran the exact restore/build/test sequence recorded in the JSON
evidence. The build uses `--no-incremental` so the recorded test assemblies
are freshly materialized; the test invocation uses `--no-build`,
`--no-restore`, no filter, and a unique TRX directory.

The scope diff received self-review. I checked the obligation mapping,
synthetic fixture strictness, source-payload exclusions, result-to-assembly
binding, skip reasons, and raw-artifact boundary. No independent reviewer was
available, so the evidence does not claim independent review.
