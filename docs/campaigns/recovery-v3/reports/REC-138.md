# REC-138 — Adversarial size, depth and diagnostic-volume bounds

## Outcome

REC-138 passed its frozen 48-case bounded diagnostic workload matrix, adjacent
parser/evaluator regressions, campaign-tool self-tests, and the complete
eight-target Release gate. No production code was changed. The permanent
fixture establishes finite behavior for malformed nesting, long malformed
hexadecimal literals, repeated parser errors under explicit limits, and large
near-matching descriptor sets.

The evidence is limited to the engine/parser diagnostic boundary. It does not
claim installed CLI, host/product, human-workflow, AI-agent or universal
conformance.

## Matrix and observations

The frozen contract contains four 12-case families:

- `DEPTH-01..DEPTH-12`: nesting depths 2, 4, 8, 16, 24, 32, 48, 64, 96,
  128, 160 and 192. Every workload returned at least one parser error, no more
  than the declared 100 diagnostics, and no `MQ9001` internal compiler
  diagnostic.
- `LITERAL-01..LITERAL-12`: malformed hexadecimal text lengths 8 through
  16,384. Every workload returned `MQ1006_InvalidHexNumber`; the public
  rendered message remained at or below `DiagnosticSafety.MaxDisplayLength`
  (512). A pre-canceled `QueryAnalyzer.Analyze` preserved
  `OperationCanceledException`.
- `VOLUME-01..VOLUME-12`: 16 through 768 repeated malformed statements with
  explicit `MaxErrors` values 3 through 14. Each parse reached the declared
  error boundary without exceeding it and returned ordinary diagnostics.
- `CANDIDATE-01..CANDIDATE-12`: 16 through 4,096 near-matching descriptor
  names. Forward and reverse enumeration produced the same five closest names;
  structured available/candidate facts remained bounded to five values, and
  ties produced catalog guidance but no arbitrary text-edit action.

The contract records workload limits, fixture identity, authority hashes and
the expected valid seed boundary before observation. It was verified 48/48
after the authoritative replay without expectation replacement.

Calibration failures are retained. The first run stopped during fixture
compilation because the `Parser` type needed an alias. The second run exposed
a fixture assertion that treated two catalog guidance suggestions as an
arbitrary-fix collection. Both corrections were test-fixture-only; no
production finding or repair was recorded. The third calibration and the
post-freeze authoritative replay passed 4/4 focused test methods.
