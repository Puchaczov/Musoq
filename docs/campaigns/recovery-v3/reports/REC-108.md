# REC-108 — Insertions, duplications and accidental paste fragments

## Outcome

REC-108 completed with a two-revision parser matrix and a separate
single-query entry-point probe. Revision 1 observed all 30 registered cases
and exposed two oracle mismatches; it remains immutable. Two independent
read-only campaign reviewers approved the source-justified revision-2
corrections. Revision 2 froze new candidate-version IDs for both mismatches
and replayed all 30 cases successfully. No production source change was
required or made.

The final parser matrix contains 14 invalid candidates, five
`valid_suspicious` cases and 11 `valid_ordinary` controls across five recovery
families. Invalid candidates require one exact Parse/Query/Error diagnostic;
quiet and legitimate-repetition controls require successful parsing with no
diagnostics. The fixture checks the diagnostic envelope, bounded query span,
explanation, documentation reference, suggested fixes and context snippet.

The matrix covers extra SELECT and ORDER separators, an unmatched closing
delimiter, repeated star modifiers, duplicate WHERE/GROUP/TAKE/ORDER clauses,
repeated function arguments and expressions, adjacent pasted fragments,
comments and string/raw literals containing structural-looking text, and
entry-point declaration/semicolon boundaries.

## Oracle correction

Revision 1 recorded 28 exact matches and two mismatches:

1. `REC-108-I06` was invalid as expected, but the parser's duplicate ORDER BY
   path emitted `MQ2009_InvalidOrderByExpression`, not the v1 generic
   `MQ2001_UnexpectedToken` expectation. Revision 2 uses
   `REC-108-I06-v2` with the observed specific code.
2. `REC-108-P01` was parser-valid because the root grammar permits
   semicolon-separated script items. `MQ2036_MultipleExecutableStatements` is
   a single-query compilation entry-point restriction, so revision 2 uses
   `REC-108-P01-v2` as `valid_suspicious` with no diagnostics.

Both reviewers independently approved these corrections against the bound
formal grammar and diagnostic sources. The v1 contract, manifest and behavior
record were not edited after observation; v2 was frozen before its final
replay. The evaluator probe separately verifies the `MQ2036` entry-point
behavior, rejects an adjacent statement without a separator with
`MQ2001_UnexpectedToken`, and permits one query after an enum declaration.

## Findings and repair judgment

- `REC-108-F01`: duplicate syntax receives a specific, actionable parse
  diagnostic where the parser has a dedicated recovery path; no generic repair
  was added.
- `REC-108-F02`: parser-root script validity and single-query compilation
  restrictions are distinct boundaries; the evidence keeps `MQ2036` at the
  compiler entry point rather than misclassifying valid parser input.
- `REC-108-F03`: repeated projected values, repeated replacement/order
  expressions, comments and literals remain valid; no implicit semantic
  deduplication is permitted.

No deterministic production defect was found, so production fixes are zero.
