# REC-088 — Mutation-test diagnostic assertions themselves

REC-088 verifies that the existing diagnostic assertions reject incorrect
structured diagnostics. The campaign runner is
`tools/diagnostic_assertion_mutation_gate.ps1`; it creates a detached temporary
worktree, applies one exact replacement at a time, runs the focused Release
test, classifies the process result, and resets the temporary worktree before
the next mutation. The campaign checkout was not modified by a mutant.

## Assertion and fixture boundary

The gate reused the existing assertions in
`src/dotnet/Musoq.Evaluator.Tests/DiagnosticContractTestAssertions.cs`,
`src/dotnet/Musoq.Evaluator.Tests/MusoqExceptionAssertions.cs`,
`src/dotnet/Musoq.Evaluator.Tests/DiagnosticContractOracleTests.cs`, and
`src/dotnet/Musoq.Converter.Tests/TargetDiagnosticReporterTests.cs`.
No new production assertion abstraction was introduced. The baseline included
the no-range generated-source test, which passed while preserving
`SourceLocation.None` for both endpoints.

## Outcome classification

The run recorded seven critical/killed mutations, zero survivors, one
equivalent parenthesization control, and one compilation-invalid assertion API
control. The compilation-invalid control was not counted as killed. A separate
controlled PowerShell process exceeded the one-second ceiling and was recorded
as `timeout`; the runner kills timed-out processes and excludes them from
effectiveness. No mutation timed out.

The five unique baseline focused targets passed before mutation execution. In
particular, the baseline accepted the correctly unknown runtime location, while
M06 failed when that location was fabricated.
